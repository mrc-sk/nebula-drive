# NebulaDrive 试用说明

一个自托管云存储系统，类似 Cloudreve。数据全部存在你自己的电脑上。

---

## 一、怎么跑起来

**Windows**：双击 `start.bat`
**Linux / macOS**：终端里执行 `./start.sh`

就这样，不需要装数据库、不需要装 Java、不需要装 Node.js。

> **Linux / macOS 提示**：从压缩包解压后可能丢失可执行权限，脚本会自动尝试补加。
> 如果还是提示权限不足，手动执行一次：
> ```bash
> chmod +x nebula start.sh
> ./start.sh
> ```

> 启动后窗口里会显示一个 `http://127.0.0.1:52xx` 的地址，**记下这个数字**。
> 浏览器通常会自动打开；没打开的话，把这个地址粘到浏览器地址栏。
>
> 端口不一定是 5212 —— 如果 5212 被别的程序占了，会自动换成 5213、5214…
> 这是正常行为。

停止服务：
- **Windows**：在黑色窗口按 `Ctrl+C`，或直接关窗口
- **Linux / macOS 前台运行**：`Ctrl+C`
- **Linux / macOS 后台运行**（`./start.sh --daemon`）：执行 `./stop.sh`

## 二、第一次使用（安装向导）

向导一共 5 步，全部保持默认就行：

| 步骤 | 保持默认即可 |
|---|---|
| 1. 欢迎 | 直接下一步 |
| 2. 环境检查 | 应该是全绿，有问题会红字提示 |
| 3. 数据库配置 | **保持 SQLite**（默认就是），不需要 MySQL |
| 4. 管理员账号 | 自己设一个用户名和密码 |
| 5. 完成 | 会自动跳转到登录页 |

**关于密码**：默认要求至少 8 位，且要含大写字母和数字。这是最近才加的限制，
所以弱密码（比如 `123456`、`abc123`）会被拒绝，别以为是 bug。

设好账号后，用它登录就能进主界面了。

## 三、可以试哪些功能

登录之后建议按这个顺序逛：

1. **上传文件** —— 拖拽或点上传。支持大文件分片，断了能续传。
2. **分享链接** —— 选中文件 → 分享，可以设提取码和有效期。
3. **版本控制** —— 覆盖同名文件会自动存历史版本，默认最多留 10 版
   （可在管理后台「站点设置」里改）。
4. **回收站** —— 删除的文件先进回收站，超过 30 天自动清理
   （后台每 6 小时扫一次，所以实际清理时间会有最多 6 小时延迟）。
   **注意：回收站里的文件仍然占配额**，直到被彻底清理。
5. **WebDAV** —— 可以用其他网盘客户端挂载。地址是 `http://127.0.0.1:52xx/dav/`，
   用户名密码就是你的管理员账号。
6. **管理后台** —— 管理员账号登录后，左侧栏有「管理」入口，可以加用户、改站点设置。
7. **离线下载** —— 后台任务里支持 HTTP / 磁力链接下载（需要机器上装了 aria2c，没有会自动回退）。

多语言：界面右下角可切换 5 种语言 —— 简体中文 / 繁體中文 / English / 日本語 / 한국어。

## 四、常见问题

**Q：Windows 双击后一闪而过 / Linux 跑完什么都没发生**
A：这样看不到报错信息。在终端里手动运行就能看到：

```bash
# Windows
start.bat
# 或：按住 Shift 右键 →「在此处打开 PowerShell 窗口」，输入 .\start.bat 回车

# Linux / macOS
./start.sh
```

按提示排查。Windows 下顺便看下杀毒软件是不是拦截了。

**Q：提示端口被占用**
A：脚本会自动换端口（5212 不行就用 5213、5214…），正常不会遇到。
真遇到了说明 5212-5241 全被占，可以关掉一些程序再试。

**Q：数据存在哪？**
A：同目录下的 `data` 文件夹里。想备份就把整个 `data` 目录复制走。
其中 `secret.key` 是加密密钥，**丢了里面的加密数据就解不开了**，备份时别漏。

**Q：怎么重置 / 重新安装？**
A：停掉服务，删掉整个 `data` 目录，重新运行启动脚本即可回到安装向导。
（会丢数据，谨慎。）

**Q：能换端口吗？**
A：可以。命令行参数：
- Windows：`nebula.exe -autoport -listen 127.0.0.1:6000`
- Linux / macOS：`./nebula -autoport -listen 127.0.0.1:6000`

注意 `-autoport` 会**忽略**配置里的端口、自己重新找一个空闲的。如果你想固定用
6000，就**去掉 `-autoport`**：

```bash
./nebula -listen 127.0.0.1:6000
```

**Q：能局域网访问吗 / 能给外网用吗？**
A：这个版本是**单实例设计**，只监听本机。如果要部署给多人用，请看项目 README 的
「部署形态」一节——有几个内存态功能（WebDAV 锁、限流、登录失败计数）多副本会不一致。
单人本地使用完全没问题。

## 五、这个版本的能力边界

试用版功能是完整的，但有几处已知限制：

- **单实例** —— 不能水平扩展多副本（原因见上一节）
- **WebDAV 的 PROPPATCH 不支持写自定义属性** —— 客户端会看到 `207 + 403`，
  这是按 RFC 4918 §9.2 的正确行为，不是 bug
- **WebDAV 的 LOCK 是进程内锁** —— 重启服务后锁会失效
- 忘记密码的话，目前只能进数据库改（`data/nebula.db`，用 SQLite 工具打开），
  没有邮件找回（邮件功能默认关闭，需要自己配 SMTP）
