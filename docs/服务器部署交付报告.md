## 四、本轮完成的四件事

### 1. 域名 `cloud.berrywing.top` + HTTPS

域名解析到 Cloudflare，回源模式 **Full**。链路：`浏览器 → Cloudflare → 源站 443 (socat TLS 终止) → 127.0.0.1:80 → 网盘`。

- `conf.ini`：`domain=cloud.berrywing.top`、`protocol=https`、`tlsMode=off`
- 源站自签证书：`/var/lib/nebuladrive/ssl/cert.pem` / `key.pem`
- 解决了最初 `525 / 521`（Cloudflare Full 需要源站 HTTPS，而源站只有 80）

> 自签证书在 Full 模式下可用，但**建议后续换成 Cloudflare Origin CA 证书**，替换两个 pem 后重启 `nebula-tls` 即可。

### 2. 工单站改用本地小模型

**运行时**：预编译 wheel 路线全部失败（GitHub Release 504、镜像超时、0.3.19 wheel 是 musl 构建在 glibc 上报 `libc.musl-x86_64.so.1` 缺失）。最终改走 **PyPI sdist 本地源码编译**：65 MB 的 sdist 内含完整 `vendor/llama.cpp`，装 `git` 后用 gcc/g++/cmake 编译出 glibc 版 `llama_cpp_python-0.3.9`。

| 项目 | 值 |
| --- | --- |
| 模型 | `/opt/llm/model.gguf`，Qwen2.5-**0.5B**-Instruct Q4_K_M，约 469 MB |
| 网关 | `/opt/llm/llm_server.py`，`127.0.0.1:8083`，`MemoryMax=900M` |
| 实测 | 模型加载 1.5 s，单次推理约 5~20 s，中文答复正常 |
| 工单站配置 | `ai.enabled=true`，`base_url=http://127.0.0.1:8083/v1` |

答复链路是**本地知识库要点 → 注入提示词 → 小模型组织语言 → 异常时回退知识库**，数据不出服务器、无外部 API 费用。知识库增强后答复会引用「1 GB 配额 / 用户组」等事实，明显好于小模型自由发挥。

> **关于「0.3B」**：主流可用的**中文**指令小模型最小档是 0.5B；真正 0.3B 级（gemma-3-270m、SmolLM2-360M）中文工单答复质量会明显下降，因此落在 0.5B。若必须严格 0.3B，替换 `model.gguf` + `deskctl.py set-ai --model` 即可，网关无需改动。

### 3. 不再暴露配置页面（尤其工单站）

初版工单站公开页有「管理后台 / AI 配置」页签，且 `/api/config` 可被公网访问——已彻底重写：

- 公开页**只保留**提交 / 查询两个页签
- `/api/config`、`/api/admin/config`、`/admin`、`/console` 一律返回 `404`，不暴露页面存在性
- 管理控制台挂**随机隐藏路径** `/<admin_path>`，需正确令牌；管理 API 只认请求头 `X-Admin-Token`
- **没有任何 Web 配置读写口**，配置改由服务器本机 `deskctl.py` 维护（`url / config / status / set-ai / test / tickets`）

### 4. 插件市场上架 10 个官方插件

全部是 v2 三文件契约（`plugin.json` + `register.go` + `co.BEGG`）的 **Python 纯钩子插件**，不启页面服务、不占端口、零 pip 依赖。由官方 Ed25519 密钥签名，信任库已写入服务器。

| # | 插件 | 作用 |
| --- | --- | --- |
| 1 | `nd-invite-code` | 注册邀请码（`onAuthRegisterBefore`），补上项目缺失的注册码能力 |
| 2 | `nd-upload-guard` | 拦截可执行文件/脚本、路径穿越、超大文件 |
| 3 | `nd-filename-clean` | 清洗文件名非法字符与过长名称 |
| 4 | `nd-quota-watch` | 配额用量超阈值预警 |
| 5 | `nd-login-brake` | 登录失败过多临时锁定 |
| 6 | `nd-share-policy` | 强制分享密码 + 有效期，禁止永久裸链 |
| 7 | `nd-audit-trail` | 关键操作写 JSONL 审计日志 |
| 8 | `nd-webdav-guard` | WebDAV 只读 / 禁删 / 目录保护 |
| 9 | `nd-sensitive-tag` | 敏感关键词命中自动打标 |
| 10 | `nd-maintenance` | 维护模式 + 站点公告（管理员放行） |

- 商店设置：`plugin.store.url = http://127.0.0.1:8084/`
- 签名校验：10/10 `present=valid=trusted=true`，平台标签 `any`
- 抽样安装并启用 `nd-invite-code`、`nd-audit-trail`：`status=running`、进程真实存在、`trusted=1`
- **其余 8 个保持「已上架、可安装」**，避免在未确认策略前改变线上行为
- 所有插件默认宽松（未配置即放行/只记日志），不会一装上就锁站

> 过程中修掉一个真实缺陷：生成器把 `init` 响应的 `hooks` 写成了字符串，宿主启用时报 `cannot unmarshal string into ... InitResult.hooks`。已改为数组，10/10 重跑握手自检通过并重新签名上架。
