# NebulaDrive 插件系统完全指南

> 适用版本：`V26-10.0-d` 及之后
> 对应代码：`backend/pkg/plugin/`（协议 + 宿主 + 安装器）、`backend/controllers/plugins.go`
> 本文所有结论均从源码逐行核对得出，不是设计文档。**凡与代码不符之处，以代码为准。**

## 0. 现状：真正的热加载已经落地

插件以**独立子进程**运行，通过 stdin/stdout 上的 JSON-RPC 2.0 与宿主通信。
**启用 = 拉起进程，禁用 = 杀进程，主服务不重启。**

| 能力 | 状态 |
|---|---|
| 插件装完即用，不改源码、不重编译主服务 | ✅ |
| 启用/禁用/重启 = 子进程启停，主服务不重启 | ✅ |
| 插件崩溃隔离（崩溃只杀子进程） | ✅，连续 5 次崩溃后转人工 |
| 崩溃自动重启（指数退避，最长 5 分钟） | ✅ |
| 首次进插件页弹协议、需滚动读完才能同意 | ✅ |
| 协议关卡在后端强制（未同意直接 403） | ✅ |
| 插件商店（远端清单 + 真实安装） | ✅ |
| 进程内 Go 插件（改源码重编译） | ✅ 仍支持，见 §7 |
| WASM / `.so` 动态库 | ❌ 有意不做，见下 |

### 为什么是子进程，而不是 `plugin.Open`

Go 原生 `plugin.Open` **只支持 Linux/macOS 且需要 cgo** —— Windows 根本编译不了，
而本项目日常在 Windows 开发、要打包给 Linux 朋友。即便跨平台可行，
它还要求工具链与依赖版本严格一致，一次升级就可能让已构建的插件失效。

WASM（wasmtime-go）需要 CGO，Go host function 绑定成本过高。

子进程方案：跨平台、语言无关（插件可以用任何语言写）、崩溃隔离、
真正的热插拔。代价是一次 IPC 往返（本地管道，亚毫秒级）。

### 三种插件形态

| 形态 | 加载方式 | 适用 |
|---|---|---|
| **进程外**（主流） | 独立可执行文件，宿主拉起并 RPC 调用 | 第三方扩展，可热插拔 |
| **进程内** | 宿主二进制里 `init()` 调 `plugin.Register` | 内置功能，零 IPC 开销 |
| 混合 | 两者同时存在，`Fire` 会依次派发 | 常见：内置补核心能力，外部做扩展 |

**业务代码对形态完全透明** —— 只调 `plugin.Fire()`，不关心 handler 在哪。

## 1. 快速上手：写你的第一个插件

抄 `examples/plugins/referer-guard/`（防盗链示例），或按下面四步：

### 1.1 目录结构

```
myplugin/
├── plugin.json     ← 必需，清单
└── myplugin        ← 可执行文件（Windows 上是 myplugin.exe）
```

### 1.2 plugin.json

```json
{
  "name": "myplugin",
  "title": "我的插件",
  "version": "1.0.0",
  "author": "你的名字",
  "description": "一句话说明这个插件做什么",
  "entry": "myplugin",
  "args": [],
  "protocolVersion": 1,
  "hooks": ["onAntiLeech"],
  "permissions": ["read-download-metadata", "write-own-datadir"],
  "license": "AGPL-3.0-only"
}
```

字段说明：

| 字段 | 必需 | 说明 |
|---|---|---|
| `name` | ✅ | 唯一标识，`[a-z0-9-_]`，2-64 字符。**不能是 Windows 保留名**（`CON`/`NUL`/`COM1`…） |
| `entry` | ✅ | 可执行文件名，**必须是单个文件名**。不带 `.exe` 后缀即可跨平台通用 |
| `protocolVersion` | ✅ | 必须等于 `1`，否则拒载 |
| `hooks` | ✅ | 声明实现哪些钩子。**未声明的钩子不会被派发** |
| `version` | | 语义化版本 `x.y.z` |
| `permissions` | | 权限声明，**仅供管理员安装前参考，宿主不校验** |
| `license` | | 默认 `AGPL-3.0-only` |

> `entry` 禁止路径分隔符。这不是形式主义：宿主会把 `<插件目录>/<entry>`
> 交给 `exec`，允许分隔符就等于让 manifest 指定插件目录外的任意可执行文件。

### 1.3 最小可运行插件（Go）

```go
package main

import (
	"bufio"
	"encoding/json"
	"os"
)

func main() {
	sc := bufio.NewScanner(os.Stdin)
	for sc.Scan() {
		var req struct {
			ID     int64           `json:"id"`
			Method string          `json:"method"`
			Params json.RawMessage `json:"params"`
		}
		if json.Unmarshal(sc.Bytes(), &req) != nil {
			continue
		}
		switch req.Method {
		case "init":
			// params: {hostVersion, hostProtocol, dataDir, config, siteUrl}
			respond(req.ID, map[string]any{
				"ok": true, "hooks": []string{"onAntiLeech"},
			}, 0, "")
		case "fire":
			// params: {hook, ctx, seq}
			respond(req.ID, map[string]any{
				"ctxPatch": map[string]any{"myFlag": true},
			}, 0, "")
		case "shutdown":
			respond(req.ID, map[string]any{"bye": true}, 0, "")
			return
		}
	}
}

func respond(id int64, result any, code int, msg string) {
	m := map[string]any{"jsonrpc": "2.0", "id": id}
	if code != 0 {
		m["error"] = map[string]any{"code": code, "message": msg}
	} else {
		m["result"] = result
	}
	b, _ := json.Marshal(m)
	os.Stdout.Write(append(b, '\n'))
}
```

**三条铁律**：

1. **stdout 专供 RPC**，一行一个 JSON。日志一律写 **stderr**
   （宿主会收集 stderr 到日志缓冲）。混用会破坏分帧，插件直接失联。
2. **`ctxPatch` 回传修改**。RPC 的 `result` 里没有"设置 ctx 字段"这种语义，
   唯一输出通道是 `ctxPatch`（浅层合并，顶层键覆盖）。
3. **拦截用 error，且文本必须含小写 `blocked`**。
   `{"error": "blocked by myplugin: 外站访问"}` → 403。
   `{"ctxPatch": {"blocked": true}}` **不会**拦截。

### 1.4 编译与安装

```bash
cd myplugin
go build -o myplugin .          # Windows: -o myplugin.exe .
```

然后在管理端「插件 → 商店」填商店地址，或直接用本地目录安装
（`POST /api/admin/plugins/install`，`{"source":"local","path":"/abs/path"}`）。

**安装不会自动启用** —— 必须显式点「启用」。这是刻意的：
自动启用会让「阅读并同意插件协议」这一步形同虚设。

## 2. 架构与核心 API

### 2.1 协议层 `pkg/plugin/`

```go
const ProtocolVersion = 1

type HookName string
type HandlerFunc func(ctx map[string]any) (map[string]any, error)

func Register(h HookName, fn HandlerFunc)   // 注册进程内 handler
func Fire(h HookName, ctx map[string]any) []error  // 派发
func List() map[HookName]int                // handler 总数
func ListSplit() (inProc, outProc map[HookName]int)  // 分别统计
func RateLimitGate(ctx map[string]any) []error       // 同步拦截门
func IsBlockedError(err error) bool
```

### 2.2 派发模式：sync / async

`Hooks` 表为每个钩子标注 `Mode`：

| 模式 | 行为 | 适用 |
|---|---|---|
| `ModeSync` | 阻塞等插件返回（超时 2s） | 业务要读结果才能决策（下载拦截、302 跳转） |
| `ModeAsync` | 每插件一个 goroutine，**结果不回传** | 纯事件通知（邮件、审计、协作保存） |

`ModeAsync` 之所以不回传 ctx：业务已经继续往下走了，回写只会造成竞态。
需要回传就用 `ModeSync`。

目前 `ModeSync` 只有 `onAntiLeech` 和 `onCollabOpen`。

### 2.3 `Fire` 不持锁执行用户代码

旧实现 `Fire` 全程持 `mu.RLock()`。现在先复制 handler 快照再放锁 ——
持锁做 IPC 往返（可达数百 ms）会把 `Register` 和 `List` 全部卡死。

进程内 handler 带 panic recover 与 5s 超时。进程外插件崩溃由宿主隔离。

### 2.4 宿主 `pkg/plugin/host/`

| 能力 | 参数 |
|---|---|
| 启动超时（含 init 握手） | 10s |
| 单次 fire 超时 | 2s |
| 崩溃自动重启 | 2s 起指数退避，最长 5 分钟 |
| 连续崩溃上限 | 5 次后停止并转人工 |
| 日志缓冲 | 每插件 500 条环形 |

进程组隔离：Windows 用 `taskkill /T /F`（否则插件的孙进程会留成孤儿），
Unix 用 `kill(-pgid)`。

## 3. 钩子清单

| 钩子 | Mode | 可拦截 | 已接入 | 说明 |
|---|---|---|---|---|
| `onAntiLeech` | sync | ✅ | ✅ | **唯一下载拦截点**，做防盗链必须用它 |
| `onCollabOpen` | sync | — | ✅ | 在 ctx 写 `url` 则 302 跳外部编辑器 |
| `onCollabSave` | async | — | ✅ | 纯通知。`content` 是完整文件明文 |
| `onEmail` | async | — | ✅ | 纯通知。**系统本身不含发信实现，此钩子是邮件外发唯一入口** |
| `onDBMigrate` | async | — | ✅ | 每次启动都触发，建表必须幂等 |
| `onRateLimit` | async | ❌ | ✅ | 见下方说明 |
| `onBackup` | async | — | ❌ | **预留未接入** |
| `onRestore` | async | — | ❌ | **预留未接入** |
| `onApiAuth` | async | — | ❌ | **预留未接入** |
| `onCLI` | async | — | ❌ | **预留未接入** |

### `onRateLimit` 的特殊处理

它在 **7 处**被调用，但只有限流中间件那一处需要读返回值做拦截决策。
若整个钩子设为 `ModeSync`，另外 6 处（登录/上传/下载/分享增删）每次都要白等 IPC 往返。

**解决**：钩子保持 `ModeAsync`（不拖累热路径），
限流中间件改调 `plugin.RateLimitGate(ctx)` —— 它走 `Dispatcher.DispatchSync`
强制同步等待。代价是最多一个 FireTimeout，且**只在有插件声明该钩子时才有实际等待**。

### 预留钩子

`onBackup` / `onRestore` / `onApiAuth` / `onCLI` 有常量、有文档，
但**后端没有任何 Fire 调用点** —— 给它们写处理器不会有任何效果。

## 4. 插件协议

首次进入插件页会弹窗，要求阅读并同意。两条硬约束：

- **必须滚动到底**才能勾选 —— 一打开就能点同意等于没要求同意；
- **后端强制**（`requireAgreement`），未同意时安装/启用接口直接 403。
  只靠前端弹窗的话，直接调 API 就能绕过。

协议正文硬编码在 `pkg/plugin/agreement.go`，不从配置文件读 ——
从外部读意味着部署者能改掉管理员看到的内容。
协议版本升级后需重新同意。

协议覆盖：插件是什么、**权限与风险**（插件与主服务同等系统权限、无沙箱）、
可观测性、拦截语义、数据与配置、许可与合规、卸载、协议变更。

## 6. 安装安全

解压一个 zip 就跑起任意代码，这里是唯一屏障：

| 风险 | 防护 |
|---|---|
| zip slip（`../../etc/passwd`） | 每条目 `filepath.Clean` 后校验前缀，越界立即**报错**（不静默跳过） |
| zip bomb | 解压总量 256MB / 单文件 64MB / 条目数 2000 三重限额 |
| 符号链接指向宿主文件 | 直接拒绝 |
| Windows 保留名插件 | 拦截（`CON`/`NUL`/`COM1`…） |
| `entry` 越界执行 | 禁止路径分隔符 + 二次前缀校验 |
| 下载非 http(s) | 只允许 http/https（挡掉 `file://`） |
| 恶意商店 URL 指向内网 | 不阻断（管理员可信），但 `IsInternalAddr` 可供提示 |
| 卸载误操作 | `RequireConfirm` 中间件，需二次确认密码 |

## 7. 进程内插件（内置功能）

仍在支持。写一个 Go 文件放进 `backend/pkg/plugin/custom/`：

```go
package plugin

func init() {
    Register(HookAntiLeech, func(ctx map[string]any) (map[string]any, error) {
        defer func() { recover() }()   // 必须
        return nil, nil
    })
}
```

需重编译宿主。适合内置能力，不适合第三方扩展。

**注意**：
- handler 内不要调 `Register`（已不持锁，但会随重启累积）
- ctx 里的字段必须带类型断言（`ctx["userId"].(uint)`）

## 8. 写文档时的诚实边界

以下是本文**故意不承诺**的：

- `permissions` 声明**不强制**，只展示给管理员看；
- 商店条目的 `version`/`author` 不可信，真实清单以下载后的 `plugin.json` 为准；
- 「已接入」的钩子才真的会被触发，预留钩子写了也白写；
- 插件的沙箱**不存在**，隔离靠进程边界 + 权限自觉。

## 10. 常见陷阱

以下多数是**进程内 handler** 的坑（进程外插件由宿主隔离，panic 不会炸宿主）。

### 7.1 handler panic 会炸掉整个请求
`Fire` 没有 `recover`。**每个 handler 都必须自己兜**：
```go
plugin.Register(plugin.HookAntiLeech, func(ctx map[string]any) (out map[string]any, err error) {
	defer func() {
		if r := recover(); r != nil {
			// 必须记日志但绝不能往上抛
			log.Printf("[antileech] panic: %v ctx=%v", r, ctx)
			err = nil   // 想放行就 err = nil
		}
	}()
	// ... 业务逻辑
	return nil, nil
})
```
### 7.2 ctx 字段必须带类型断言
ctx 是 `map[string]any`，取出的是 `interface{}`。**直接 `. (string)` 或直接当 int 用会 panic**：
```go
// 错：
id := ctx["userId"].(int)          // 实际是 uint，panic
n := ctx["size"].(int)             // 实际是 int64
// 对：
if id, ok := ctx["userId"].(uint); ok {
	log.Printf("user=%d", id)
}
size, _ := ctx["size"].(int64)
name, _ := ctx["fileName"].(string)
```
同一字段在不同钩子里的类型可能不同（如 `share.go:287` 的 `userId` 是分享所有者 ID，访客未登录）。
### 7.3 不要在 handler 里 Register
`Fire` 全程持 `mu.RLock()`，`Register` 需要 `mu.Lock()`。handler 内调 `Register` → **Go 的 `sync.RWMutex` 不可重入 → 死锁，进程直接卡住**。
### 7.4 ctx 会被后续 handler 看见
`ctx` 是同一个 map 引用，串行传给该钩子的所有 handler，且 `Fire` 不会回滚任何修改。恶意/有 bug 的插件可以篡改后面插件看到的数据。关键 ctx 建议先自己拷一份再改。
### 7.5 拦截靠字符串匹配，不是布尔字段
```go
// 无效：
return map[string]any{"blocked": true}, nil
ctx["blocked"] = true
// 有效：
return nil, fmt.Errorf("blocked: 外网 IP 访问")
return nil, errors.New("blocked")
```
必须走 `error`，且文本含小写 `blocked` 子串。大写 `Blocked` 不匹配（`strings.Contains` 区分大小写）。
### 7.6 只有 2 个触发点真正响应拦截
再强调一次：`onRateLimit` 的 7 个触发点里，只有 `middleware/rate_limit.go` 会检查 error。需要**拦请求**的逻辑请放 `onAntiLeech`（下载前），或依赖全局限流中间件。
### 7.7 `onDBMigrate` 每次启动都触发
不是「首次升级才触发」。`fromVersion == toVersion` 表示本次没有任何迁移，插件仍会被调用。自己建表要写成幂等的（`CREATE TABLE IF NOT EXISTS`），否则重复执行会报错。
### 7.8 未接入的钩子写了也白写
`onBackup` / `onRestore` / `onApiAuth` / `onCLI` 目前无 `Fire` 点。别浪费时间。
