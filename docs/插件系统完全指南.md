# NebulaDrive 插件系统完全指南

> 适用版本：`V26-10.0-c` 及之后
> 对应代码：`backend/pkg/plugin/hooks.go`（全部 65 行）、`backend/controllers/`、`backend/middleware/`
> 本文所有结论均从源码逐行核对得出，不是设计文档。**凡与代码不符之处，以代码为准。**

---

## 0. 一句话现状（请先读这一节）

NebulaDrive 的插件系统目前是一个**「进程内事件钩子骨架」**，不是动态可加载的插件体系。

| 能力 | 状态 |
|---|---|
| 钩子注册与派发（`Register` / `Fire`） | ✅ 可用，并发安全 |
| 后端在业务代码里触发钩子 | ✅ 6 个钩子共 **12 个触发点** |
| 运行时动态加载第三方插件（`.so` / 子进程 / WASM） | ❌ **不存在** |
| 插件装完即用、不改源码、不重编译 | ❌ **不存在** |
| 管理端「启用/禁用」开关真正控制插件生效 | ❌ **未接线**（见 §6.2） |
| 插件商店「安装」按钮 | ❌ 弹 `alert()` 占位 |

**这意味着什么**：要加一个插件，唯一可行的路径是 —— 写一个 Go 文件放进 `backend/`，在里面 `init()` 里调 `plugin.Register`，然后**重新编译整个后端**。这是设计上的取舍（不引入 `plugin.Open` 的跨平台与 ABI 脆弱性），但当前代码里连一条注册链路都没有，等于连这条路都还没铺好。

下文会逐条给出证据，并给出**照着抄就能跑通**的接入步骤（§5）与**可直接使用的示例插件**（§6）。

## 1. 核心 API

全部实现在 `backend/pkg/plugin/hooks.go`：

```go
package plugin

type HookName string
type HandlerFunc func(ctx map[string]any) (map[string]any, error)

func Register(h HookName, fn HandlerFunc)  // 追加一个处理器
func Fire(h HookName, ctx map[string]any) []error  // 派发，返回所有非 nil error
func List() map[HookName]int               // 各钩子当前处理器数量
var HookDocs map[HookName]string           // 硬编码的中文描述（供前端展示）
```

### 1.1 10 个钩子名

```go
HookEmail      HookName = "onEmail"
HookBackup     HookName = "onBackup"
HookRestore    HookName = "onRestore"
HookApiAuth    HookName = "onApiAuth"
HookDBMigrate  HookName = "onDBMigrate"
HookRateLimit  HookName = "onRateLimit"
HookAntiLeech  HookName = "onAntiLeech"
HookCLI        HookName = "onCLI"
HookCollabOpen HookName = "onCollabOpen"
HookCollabSave HookName = "onCollabSave"
```

### 1.2 `Fire` 的返回值 map 被丢弃

这是最容易踩的坑。源码：

```go
func Fire(h HookName, ctx map[string]any) []error {
	mu.RLock()
	defer mu.RUnlock()
	var errs []error
	for _, fn := range registry[h] {
		if _, err := fn(ctx); err != nil {   // ← 返回的 map 被 "_" 丢弃
			errs = append(errs, err)
		}
	}
	return errs
}
```

`HandlerFunc` 返回的 `map[string]any` **完全不会被合并、也不会传给调用方**。所以：

- ❌ `return map[string]any{"blocked": true}, nil` —— **无效**
- ✅ 修改传入的 `ctx`（map 是引用类型）—— **有效**，这是唯一的输出通道
- ✅ 返回 `error` —— 有效，但**不同触发点对 error 的处理完全不同**（见 §4）

同时注意：**多个 handler 共享同一个 `ctx`**，且按 `Register` 顺序串行执行（`Fire` 全程持 `RLock`，所以 handler 内部再调 `Register` 会死锁）。一个 handler 改了 `ctx`，后面所有 handler 看到的就是改后的值。

### 1.3 `Fire` 不做 panic 恢复

`Fire` 里没有 `recover()`。你的 handler 一旦 panic，异常会直接穿透到 gin 的 Recovery 中间件 —— 整个请求变成 500，而钩子里其他 handler 全部没执行。

```go
plugin.Register(plugin.HookAntiLeech, func(ctx map[string]any) (map[string]any, error) {
	panic("boom")   // ← 整个下载请求 500，且同钩子的其他插件全被跳过
})
```

**必须自己写 `defer func(){ recover() }()`**，见 §7.1。

## 3. 已生效钩子详解

### 3.1 `onRateLimit` —— 限流 / 高频操作审计

**触发点分布（7 处，语义不一致）**：

| 文件:行 | 场景 | ctx 字段 | 拦截能力 |
|---|---|---|---|
| `middleware/rate_limit.go:99` | 全局限流中间件（按 category） | `category` `ip` `ua` `path` `userId`? `userName`? | ✅ **唯一可拦截** |
| `controllers/auth.go:99` | 登录成功后 | `userId` `userName` `ip` `ua` `action` | ❌ 仅观察 |
| `controllers/file.go:359` | 上传成功后 | `userId` `userName` `ip` `ua` `fileId` `fileName` `size` | ❌ 仅观察 |
| `controllers/file.go:404` | 登录态下载（AntiLeech 之后） | `fileId` `fileName` `referer` `userId` `userName` `ip` `ua` | ❌ 仅观察 |
| `controllers/share.go:99` | 创建分享 | `userId` `userName` `ip` `ua` `shareId` `fileId` `fileName` | ❌ 仅观察 |
| `controllers/share.go:287` | 公开分享下载 | `userId`(分享所有者) `userName`(空串) `ip` `ua` `shareId` | ❌ 仅观察 |
| `controllers/share.go:431` | 删除分享 | `userId` `userName` `ip` `ua` `shareId` | ❌ 仅观察 |

**拦截语义**（仅 `middleware/rate_limit.go` 生效）：

```go
if errs := plugin.Fire(plugin.HookRateLimit, ctx); len(errs) > 0 {
	for _, e := range errs {
		if strings.Contains(e.Error(), "blocked") {   // ← 必须是 error 文本里含 "blocked"
			c.AbortWithStatusJSON(403, gin.H{"code": 403, "message": "blocked by rate limit plugin"})
			return
		}
	}
}
```

要点：
- **必须返回 `error`**，且 `err.Error()` 里包含子串 `blocked`。
- 返回其他 error（比如 `"quota exceeded"`）**会被完全忽略**，请求正常通过。
- 返回 `nil` 错误或 `ctx["blocked"]=true` 都没有拦截效果。
- 多个 handler 时，**任一**返回含 `blocked` 的 error 即拦截。

**字段类型**：`userId` 是 `uint`，`ip`/`ua`/`action` 是 `string`，`fileId` 是 `uint`，`size` 是 `int64`。取值时务必用带类型断言的写法，见 §7.2。

### 3.2 `onAntiLeech` —— 下载防盗链（唯一下载拦截点）

**触发点**：`controllers/file.go:396`（`Download` 内，权限校验通过之后、真正读文件之前）

**ctx 字段**：

| 键 | 类型 | 值 |
|---|---|---|
| `userId` | `uint` | 下载者 ID |
| `userName` | `string` | 下载者用户名 |
| `ip` | `string` | `c.ClientIP()` |
| `ua` | `string` | `c.Request.UserAgent()` |
| `fileId` | `uint` | 文件 ID |
| `fileName` | `string` | 文件名 |
| `referer` | `string` | `c.GetHeader("Referer")`，无则空串 |

**拦截语义**：

```go
if errs := plugin.Fire(plugin.HookAntiLeech, dctx); len(errs) > 0 {
	for _, e := range errs {
		if strings.Contains(e.Error(), "blocked") {
			c.JSON(403, gin.H{"code": 1, "message": "blocked by anti-leech"})
			return
		}
	}
}
```

同样是「error 文本含 `blocked`」。**这是唯一能在下载前拿到 `fileId` + `referer` 并真正拦住请求的钩子** —— 想做防盗链必须用它，不要用 `onRateLimit`。

注意：**公开分享下载不走这个钩子**。分享下载在 `serveShareFile` 里，只触发了 `onRateLimit` 且是观察型（`share.go:287`）。要给分享下载加防盗链，得等 §8 的接入方案。

### 3.3 `onCollabOpen` —— 协作编辑打开（可重定向）

**触发点**：`controllers/collab.go:49`

**ctx 字段**：

| 键 | 类型 | 值 |
|---|---|---|
| `userId` | `uint` | 打开者 |
| `userName` | `string` | 打开者 |
| `fileId` | `uint` | 文件 ID |
| `fileName` | `string` | 文件名 |
| `mimeType` | `string` | MIME |
| `ip` | `string` | 客户端 IP |

**输出方式**（这是唯一一个「返回值 map 有效」的钩子 —— 但实际机制是**改 ctx**）：

```go
plugin.Fire(plugin.HookCollabOpen, ctx)
if url, ok := ctx["url"].(string); ok && url != "" {
	c.Redirect(http.StatusFound, url)   // 302 跳外部编辑器
	return
}
// 没有钩子且文件是 md/txt → 返回 {mode:"yjs", docId}
```

所以接 OnlyOffice / WPS WebOffice 的正确做法是：

```go
plugin.Register(plugin.HookCollabOpen, func(ctx map[string]any) (map[string]any, error) {
	token := buildOnlyOfficeToken(ctx)      // 用 ctx 里的 fileId/文件数据签名
	ctx["url"] = "https://onlyoffice.example.com/editor?fileId=" + token
	return nil, nil                          // 返回值无所谓
})
```

**注意**：跳转目标若需要密码/提取码，得自己拼进 URL；外部编辑器回调保存的钩子不存在（见 §4）。

### 3.4 `onCollabSave` —— 协作保存（仅观察）

**触发点**：`controllers/collab.go:113`（`CollabSave` 内，配额校验通过后、写入前）

**ctx 字段**：

| 键 | 类型 | 值 |
|---|---|---|
| `userId` | `uint` | 保存者 |
| `userName` | `string` | 保存者 |
| `fileId` | `uint` | 文件 ID |
| `fileName` | `string` | 文件名 |
| `content` | `string` | **完整文件内容** |

**拦截语义：无。** 调用的返回值被完全忽略，error 也不看。这是纯审计/备份/外部回写钩子。

⚠️ `content` 是**整个文件明文**。在这里做全文扫描/备份的插件会显著增加内存占用，大文件要小心。

### 3.5 `onEmail` —— 邮件发送

**触发点**：`controllers/ws.go:122`，在 `CreateNotification(userID, title, body, ntype, category)` 内部 —— 站内信落库并通过 WebSocket 推送**之后**。

> 注意别被函数名骗了：`NotifyUser`（`ws.go:92`）只做 WebSocket 推送，不触发钩子。钩子在它上面的 `CreateNotification` 里。

**ctx 字段**：

| 键 | 类型 | 值 |
|---|---|---|
| `to` | `string` | 收件邮箱 |
| `subject` | `string` | 通知标题 |
| `body` | `string` | 通知正文 |

**触发前提**：目标用户的 `Email` 字段非空。为空则整个 `Fire` 跳过。

**实际只有 5 个调用场景**（`grep CreateNotification` 的全部结果）：

| 场景 | 标题 | 来源 |
|---|---|---|
| 管理员创建账号 | 「欢迎加入」 | `admin.go:70` |
| 套餐兑换成功 | 「套餐兑换成功」 | `plan.go:431` |
| 分享被访问 | 「分享被访问」 | `share.go:156` |
| 离线/传输任务下载完成 | 「下载完成」 | `task.go:357` |
| 同上（另一处） | 「下载完成」 | `task.go:466` |

⚠️ **与 `HookDocs` 不符**：`HookDocs[HookEmail]` 写的是「可拦截注册激活、找回密码等邮件」，但**代码里没有任何调用 `CreateNotification` 的地方与注册激活或找回密码相关**。邮箱验证码走的是 `EmailCode` 模型（`models/models.go` 里有注册），但 `controllers/` 里搜不到任何 `smtp` / `SendMail` / 发信调用。

**拦截语义：无。** 也就是说 —— **系统目前完全没有内置发信能力**。这封邮件是「站内通知要不要额外发一封邮件」的唯一入口，全靠插件实现。

⚠️ `body` 可能是 HTML。实现 SMTP 插件时注意不要把用户可控内容直接拼进邮件头，否则能被邮件头注入。

### 3.6 `onDBMigrate` —— 数据库迁移完成

**触发点**：`migrations/migrate.go:117`，`AutoMigrate` + 记录版本号全部完成后，**每次启动都会触发一次**。

**ctx 字段**：

| 键 | 类型 | 值 |
|---|---|---|
| `fromVersion` | `int` | 迁移前版本号（全新安装为 0） |
| `toVersion` | `int` | 迁移后版本号 |

**这是唯一一个适合「自行建表/加索引」的钩子**，示例见 §6.5。返回的 error 同样被忽略。

⚠️ 这里的数据库句柄得你自己拿（`db.Get()`），钩子签名不提供连接。

## 4. 预留未接入的 4 个钩子

`onBackup` / `onRestore` / `onApiAuth` / `onCLI` 在 `hooks.go` 里有常量、有 `HookDocs` 描述、有 `ListPluginHooks` 里的展示条目，**但后端没有任何一处 `plugin.Fire`**。

也就是说：**给它们写 handler 代码不会有任何效果**，因为没人调用它们。

它们的 ctx 字段在代码里也无从考证 —— `HookDocs` 只有一句中文描述，前端 `Plugins.tsx` 里的 `HOOKS` 数组虽有描述（`ctx={targetDir}`、`ctx={backupFilePath}`、`ctx={token, req}`），但那段描述**纯粹是前端硬编码的文案**，与后端不对应，不要当作契约。

| 钩子 | `Hooks.tsx` 声称的 ctx | 实际 |
|---|---|---|
| `onBackup` | `{targetDir}` | 无 Fire 点，字段无法验证 |
| `onRestore` | `{backupFilePath}` | 无 Fire 点，字段无法验证 |
| `onApiAuth` | `{token, req}`，返回 `ctx.granted=true` | 无 Fire 点，字段无法验证 |
| `onCLI` | `nebula plugin exec <name>` | 无 Fire 点，且**不存在该 CLI 子命令** |

补充说明 —— 它们各自缺的是哪一步：

- **`onApiAuth`**：现有鉴权就是「查 `sessions` 表比对 token + 过期时间」，没有任何外部身份源介入点。相关代码在 `middleware/auth.go` 与 `controllers/auth.go`。
- **`onBackup` / `onRestore`**：路由里 `router.go:218` 的 `/:id/restore` 和 `:226` 的 `/versions/:vid/restore` 是**回收站还原与历史版本还原**，与「整库备份/恢复」不是一回事。系统没有整库备份功能，也就没有这两处 `Fire` 该放的位置。
- **`onCLI`**：`main.go` 里没有任何子命令分发逻辑（无 cobra、无 `flag` 子命令解析），要加等于先引入一套命令行框架。


另有一点：前端的 `HOOKS` 数组只列了 8 个，**漏了 `onCollabOpen` 和 `onCollabSave`**（后端 `/api/admin/plugins/hooks` 仍会返回全部 10 个）。

想让这 4 个钩子真正可用，需要先在业务代码里补 `Fire` 调用点 —— 见 §8.2。

## 5. 编写你的第一个插件（完整流程）

### 5.1 唯一可行的接入方式

因为没有动态加载，必须改源码。步骤：

1. 新建 `backend/pkg/plugin/custom/myplugin.go`
2. 在 `init()` 里 `plugin.Register(...)`
3. 确认该文件被编译进主二进制（默认同包即自动编译，无需 import）
4. 重新编译

```
backend/
└── pkg/plugin/
    ├── hooks.go          ← 系统自带，不要改
    ├── hooks_test.go
    └── custom/           ← 你新建的目录（放同一包或新包都行）
        └── antileech.go  ← 你的插件
```

⚠️ `custom/` 目录名没有特殊含义，Go 只认 `package` 声明。放在 `pkg/plugin/` 下用 `package plugin` 最省事（可直接用 `Register`/`Fire`/`HookName`）；若想隔离成 `package myplugin`，则需写 `plugin.Register(...)` 并 import `github.com/nebula-drive/nebula/pkg/plugin`。

### 5.2 最小可运行示例

`backend/pkg/plugin/custom/echo.go`：

```go
package plugin

// init 在包被加载时自动执行，无需任何注册中心
func init() {
	Register(HookAntiLeech, func(ctx map[string]any) (map[string]any, error) {
		// 只观察，不拦截
		name, _ := ctx["fileName"].(string)
		_ = name
		return nil, nil
	})
}
```

就这么简单。重新编译后，去「管理后台 → 插件 → 扩展点」页面（见 §6 关于该页面当前不可用的说明），或直接调接口看：

```bash
curl -H "Authorization: Bearer <管理员token>" \
     http://127.0.0.1:8080/api/admin/plugins/hooks
```

`onAntiLeech` 的 `count` 会从 0 变成 1。

### 5.3 编译

```bash
cd backend
export GOPROXY=off        # 依赖已缓存时最稳，避免代理挂起
go build -o nebula.exe .
```

Windows 上临时文件必须放在 Windows 可见路径，`/tmp` 对 Go 工具链不可见。

## 6. 管理端 API

### 6.1 四个路由

`backend/routers/router.go:164-167`，均在 `/api/admin` 组下，需管理员登录（`Auth(true)` + `AdminOnly()`）：

| 方法 | 路径 | 控制器 | 作用 |
|---|---|---|---|
| GET | `/api/admin/plugins` | `ListPlugins` | 读 `plugins` 表全部记录 |
| POST | `/api/admin/plugins/:id/toggle` | `TogglePlugin` | 翻转 `enabled` 布尔值 |
| GET | `/api/admin/plugins/store` | `StorePluginCatalog` | 代理远端 `com.json` |
| GET | `/api/admin/plugins/hooks` | `ListPluginHooks` | 返回 10 个钩子名 + 处理器数 + 中文描述 |

**`/hooks` 响应示例**：

```json
{
  "code": 0,
  "data": [
    { "name": "onEmail",      "count": 0, "doc": "邮件发送钩子：可拦截注册激活…" },
```

### 6.2 `plugins` 表与「启用/禁用」开关

模型在 `backend/models/session.go:28`：

```go
type Plugin struct {
	ID        uint      `gorm:"primarykey" json:"id"`
	Name      string    `gorm:"uniqueIndex;size:64;not null" json:"name"`
	Title     string    `gorm:"size:128" json:"title"`
	Enabled   bool      `gorm:"default:false" json:"enabled"`
	Config    string    `gorm:"type:text" json:"-"`   // JSON，但不对外输出
	CreatedAt time.Time `json:"createdAt"`
}
```

**关键事实：`enabled` 字段目前没有任何生产代码读取。**

```bash
cd backend
grep -rn "Enabled" --include=*.go . | grep -i plugin
# 唯一命中：controllers/handlers_test.go:286（测试数据）
```

后果：
- `TogglePlugin` 只翻转数据库里的布尔值，**不影响任何 handler 是否执行**。
- `Config` 字段带 `json:"-"`，管理端接口拿不到，无法从后台给插件下发配置。
- 表里也没有向 `Register` 的同步逻辑 —— 即使 `enabled=true`，也不会凭空出现 handler。

所以「先写好插件代码 → 后台打开开关 → 生效」这条路走不通。**实际生效的唯一判据是：进程重启后 `in-process registry` 里有没有你的 handler。**

### 6.3 插件商店

`StorePluginCatalog` 的逻辑：从 `settings` 表读 `plugin.store.url`（管理员在前端「插件商店」页保存），拼上 `/com.json`，用 10 秒超时的 `http.Client` 直接 GET 回来**原样透传**给前端。

```go
storeURL += "com.json"
resp, err := client.Get(storeURL)
// 任何出错都返回空数组，不报错
c.Data(http.StatusOK, "application/json; charset=utf-8", body)
```

- `plugin.store.url` **没有默认值**，必须是管理员在页面上填过。
- 出错（URL 错、网络不通、响应体读失败）一律返回 `{"code":0,"data":[]}`，**不会报错**，所以页面永远显示空列表，不告诉用户到底哪里错了。
- 远端返回什么就是什么，**没有字段校验、没有签名校验**。这是 SSRF 面：管理员可把 URL 指向内网地址。管理员权限下风险可控，但要知道它存在。
- 前端「安装」按钮是 `alert(\`Install plugin: ${p.name}\`)`，纯占位。

### 6.4 前端插件页的两个缺陷

页面在 `frontend/src/pages/admin/Plugins.tsx`。**访问它之前请先知道**：

1. **扩展点数是假的。** `client.ts` 里**没有** `pluginsHooks` 方法，代码里 fallback 到 `(api as any).get?.(...)` —— 也不存在。于是 `Promise.allSettled` 里这一项 resolve 成 `undefined`，走进 else 分支：

   ```ts
   const mock: Record<string, number> = {}
   HOOKS.forEach((h) => { mock[h.key] = Math.max(0, Math.floor(Math.random() * 5) - 1) })
   setHooks(mock)
   ```

   **页面上显示的 handler 数量每次刷新都是随机数**，与真实注册情况无关。真实数量必须调 `/api/admin/plugins/hooks` 才能拿到。
   
2. **「安装」是占位。** 同上，`alert()` 而已。

这两点是代码事实，与 §0 表格一致。修复方案见 §8.3。

## 7. 常见陷阱

### 7.1 handler panic 会炸掉整个请求

`Fire` 没有 `recover`。**每个 handler 都必须自己兜**：

```go
plugin.Register(plugin.HookAntiLeech, func(ctx map[string]any) (out map[string]any, err error) {
	defer func() {
		if r := recover(); r != nil {
			// 必须记日志但绝不能往上抛
			log.Printf("[antileech] panic: %v ctx=%v", r, ctx)
			err = nil   // 想放行就 err = nil
		}
	}()
	// ... 业务逻辑
	return nil, nil
})
```

### 7.2 ctx 字段必须带类型断言

ctx 是 `map[string]any`，取出的是 `interface{}`。**直接 `. (string)` 或直接当 int 用会 panic**：

```go
// 错：
id := ctx["userId"].(int)          // 实际是 uint，panic
n := ctx["size"].(int)             // 实际是 int64

// 对：
if id, ok := ctx["userId"].(uint); ok {
	log.Printf("user=%d", id)
}
size, _ := ctx["size"].(int64)
name, _ := ctx["fileName"].(string)
```

同一字段在不同钩子里的类型可能不同（如 `share.go:287` 的 `userId` 是分享所有者 ID，访客未登录）。

### 7.3 不要在 handler 里 Register

`Fire` 全程持 `mu.RLock()`，`Register` 需要 `mu.Lock()`。handler 内调 `Register` → **Go 的 `sync.RWMutex` 不可重入 → 死锁，进程直接卡住**。

### 7.4 ctx 会被后续 handler 看见

`ctx` 是同一个 map 引用，串行传给该钩子的所有 handler，且 `Fire` 不会回滚任何修改。恶意/有 bug 的插件可以篡改后面插件看到的数据。关键 ctx 建议先自己拷一份再改。

### 7.5 拦截靠字符串匹配，不是布尔字段

```go
// 无效：
return map[string]any{"blocked": true}, nil
ctx["blocked"] = true

// 有效：
return nil, fmt.Errorf("blocked: 外网 IP 访问")
return nil, errors.New("blocked")
```

必须走 `error`，且文本含小写 `blocked` 子串。大写 `Blocked` 不匹配（`strings.Contains` 区分大小写）。

### 7.6 只有 2 个触发点真正响应拦截

再强调一次：`onRateLimit` 的 7 个触发点里，只有 `middleware/rate_limit.go` 会检查 error。需要**拦请求**的逻辑请放 `onAntiLeech`（下载前），或依赖全局限流中间件。

### 7.7 `onDBMigrate` 每次启动都触发

不是「首次升级才触发」。`fromVersion == toVersion` 表示本次没有任何迁移，插件仍会被调用。自己建表要写成幂等的（`CREATE TABLE IF NOT EXISTS`），否则重复执行会报错。

### 7.8 未接入的钩子写了也白写

`onBackup` / `onRestore` / `onApiAuth` / `onCLI` 目前无 `Fire` 点。别浪费时间。

## 8. 把骨架补成真插件体系

如果你要动手改造，以下是缺口清单与建议做法。

### 8.1 最小闭环（改动最小、收益最大）

在 `main.go` 的 `bootstrap()` 里加一个插件装配函数：

```go
// pkg/plugin/loader/loader.go
package loader

import "github.com/nebula-drive/nebula/pkg/plugin"

// 编译期已注册的内置插件
func Builtin() {
	registerAntiLeech()  // 防盗链
	registerSMTP()        // 发信
	registerOnlyOffice()  // 外部编辑器
}
```

然后在 `main.go` 的 `db.Init` 成功**之后**、`router` 装配**之前**调 `loader.Builtin()`。

`onDBMigrate` 需要小心：它在 `migrations.Apply` 内部触发，而 `migrations.Apply` 也在 bootstrap 早期执行。所以**想在 `onDBMigrate` 里建表，得用 `init()` 注册**（`init` 早于一切 `main` 流程），而不能在 `loader.Builtin()` 里注册（那时迁移可能已经跑完了）。

### 8.2 接入预留钩子需要补的 Fire 点

| 钩子 | 建议 Fire 位置 |
|---|---|
| `onApiAuth` | `middleware/auth.go` 的 Token 校验处、`controllers/auth.go` 的登录校验处 |
| `onBackup` | 新增 `controllers/admin_backup.go` 的备份动作前后 |
| `onRestore` | 新增恢复动作入口处 |
| `onCLI` | `main.go` 解析 `os.Args`，命中 `plugin exec <name>` 时派发 |

补 `onApiAuth` 时建议**约定好契约**，例如：

```go
// 请求前：ctx 带 token/method/path
// 通过：ctx["granted"] = true
// 拒绝：return nil, errors.New("blocked: 身份源拒绝")
if errs := plugin.Fire(plugin.HookApiAuth, ctx); len(errs) > 0 {
	for _, e := range errs {
		if strings.Contains(e.Error(), "blocked") {
			c.AbortWithStatusJSON(401, ...)
			return
		}
	}
}
```

### 8.3 修前端两个缺陷

1. 在 `frontend/src/api/client.ts` 的 `admin` 命名空间补：

   ```ts
   pluginsHooks: () => request<ApiResult<any[]>>('/api/admin/plugins/hooks'),
   ```

2. `Plugins.tsx` 里删掉随机数 mock 分支，改为接口失败时显式提示；把 `HOOKS` 数组补上 `onCollabOpen` / `onCollabSave`（或直接用接口返回的 `doc` 渲染，删掉前端硬编码文案）。

### 8.4 开关与配置真正接线

若要实现「后台开关控制插件」，需要：
1. `models.Plugin` 增加 `HookName` 字段，标识绑定哪个钩子
2. 启动时从库里读 `enabled=true` 的记录，只注册它们
3. `TogglePlugin` 改动后触发一次重载（或直接重启服务，语义更清晰）
4. 去掉 `Config` 的 `json:"-"`，加一个读写配置的接口
5. 明确重启语义 —— 进程内 registry 无法热卸载，单靠删 handler 会让已 `Register` 的闭包继续跑

### 8.5 动态加载（进阶，非必须）

若真需要「不改源码装插件」，可选方案与代价：
- **`plugin.Open`（Go 原生）**：只支持 Linux/macOS + cgo，且与 Go 版本、依赖版本强绑定，交叉编译困难。**不推荐**。
- **外部进程 + HTTP/IPC**：插件是独立可执行文件或脚本，通过 localhost socket 通信。跨平台、隔离性好、易热插拔，代价是每次 `Fire` 有 IPC 延迟。**推荐**。
- **WASM（wasmtime-go）**：隔离最好、可沙箱，代价是工程量大、Go host function 绑定繁琐。

无论选哪种，都建议先把 §8.1～8.4 做完 —— 现有骨架的问题是「连编译期注册链路都没通」，不是「加载方式不够先进」。
