## 3. 关键设计决策（明天别推翻）

### 3.1 为什么用子进程而不是 Go plugin.Open

`plugin.Open` 只支持 Linux/macOS 且需 cgo —— **Windows 根本编译不了**，
而本项目日常在 Windows 开发、要打包给 Linux 朋友。WASM 需 CGO，
Go host function 绑定成本过高。子进程方案跨平台、崩溃隔离、真热插拔。

### 3.2 12 个 `plugin.Fire` 调用点一行都没改

靠 `Hooks` 表里的 `Mode` 字段分流：
- `ModeSync`（`onAntiLeech` / `onCollabOpen`）：阻塞等 IPC 结果
- `ModeAsync`（其余）：每插件一个 goroutine，**结果不回传**
  （业务已经继续往下走了，回写 ctx 只会造成竞态）

`onRateLimit` 是矛盾点（7 处调用但只有 1 处检查返回值），
**当前取 `ModeAsync` + `Blockable:false`** —— 即中间件那处的插件拦截暂不生效。
这是个**已知的待办**，见 §5.3。

### 3.3 `Fire` 不持锁执行用户代码

旧实现 `Fire` 全程持 `mu.RLock()`，若在锁内做 IPC 往返（可达数百 ms），
`Register` 和 `List` 会被卡死。新实现先 `snapshot()` 复制 handler 再放锁。

### 3.4 拦截语义保持字符串匹配

`strings.Contains(err.Error(), "blocked")`（大小写敏感）。
`FireResult` **故意没有 `Blocked` 字段**，让进程内/进程外两种形态语义完全一致。

如果觉得 5 分钟太久，管理员得手动重启插件 —— 这是刻意的（防刷屏），
但值得在 UI 上说明。
