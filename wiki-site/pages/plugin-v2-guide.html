NebulaDrive 插件平台 v2 完全指南

适用：本次「插件平台 v2」改造后的代码。 与仓库里既有的 插件系统完全指南.md 是互补关系：那份讲 v1 进程外子进程机制（至今仍是正确且未改动的），本文讲 v2 新增的协议、契约、页面、UI 扩展点。 代码为准：backend/pkg/plugin/、backend/internal/pluginhttp/、backend/internal/hooks/、frontend/src/store/pluginUI.ts。

0. 一页速览

设计主线：宿主只提供钩子与插槽，业务大功能交给社区插件；同时把「开放」带来的风险用「默认关闭 + 显式确认」圈起来。

1. 兼容策略：v2 宿主，v1 插件一行不改

这是硬要求，落地在四处，缺一不可：

  1. 清单校验放宽：Manifest.Validate 接受 protocolVersion ∈ [1, 2]（原来是「必须等于当前版本」）。
  2. 握手降级：host.handshakeProtocol(declared) —— v1 老插件（如仓库自带的 examples/plugins/referer-guard）在 init 里硬校验 HostProtocol == 1，宿主若直接下发 2 会被明确拒绝。因此宿主对声明 v1 的插件在握手时表现为 v1；v1 钩子名与派发语义本来就冻结了。
  3. 三文件豁免：LoadContract 检测到 protocolVersion < 2 立即置 V1=true 返回，不要求 register.go / co.BEGG。
  4. 钩子冻结：Hooks 表里 Since=1 的钩子（含 onAntiLeech、onCollabOpen、onApiAuth、onCLI、onBackup 等）名字、模式、payload 语义完全不变。

端到端回归：pkg/plugin/host/example_test.go 用未修改的 referer-guard 源码跑通「编译 → 安装 → 加载 → 拦截 → 卸载」。

2. 三文件契约

v2 插件必须同时有这三个文件，但可以散落在任意子目录：

文件 职责 格式 谁解析
plugin.json 身份 / 协议版本 / hooks / 权限 / pages / providers JSON（严格，未知字段报错） ParseManifest
register.go 纯声明：版本、安装内容、hooks、runtime、home Go 语法的字面量，不编译 ParseGoDecl（go/parser 只读 AST）
co.BEGG runtime、解释器要求、主页、listen、页面、UI 扩展点 JSON（严格） ParseBegg

2.1 register.go 为什么叫 .go 却不编译

宿主只用标准库 go/parser / go/ast 读语法树，把 var Spec = ...{...} 里的字面量取出来：

package ass

// NotARealType 根本不存在也没关系 —— 宿主不编译、不执行、不要求服务器装 Go
var Spec = NotARealType{
    Name:            "ass-demo",
    Version:         "1.0.0",
    ProtocolVersion: 2,
    Hooks:           []string{},
    Provides:        []string{},
    Install:         []string{"in.php", "co.BEGG"},
    Runtime:         "php",
    Home:            "in.php",
}

可识别的变量名：Spec / Plugin / PluginSpec / Declaration。字段大小写不敏感（Name / name 都行）。这么设计是为了让插件作者在 IDE 里有高亮和注释，同时不破坏「宿主是单二进制、部署机什么都不用装」的承诺。

2.2 目录形式不限定：三个「Dir」别混用

Contract 有三个目录字段，这是最容易踩坑的地方：

字段 含义 用作什么
Dir 插件安装根目录 plugins/<name>/，始终等于调用方传入的目录 JSON-RPC entry 的 ExecPath 基准、NB_PLUGIN_DIR、host.Load
ManifestDir plugin.json 实际所在目录（递归定位结果） 诊断展示
BeggDir co.BEGG 实际所在目录 页面服务的工作目录，也是 co.BEGG 里 home / entry / static 的解析基准

也就是说：把 co.BEGG 和一堆 .php 一起放进 ASS/，home 直接写 "in.php" 即可；不用写 "ASS/in.php"。

locateFile 从 Dir 递归找三文件（深度 ≤ 5），跳过 . 开头目录、node_modules、__pycache__、vendor。install.InstallFromDir 复制整个源目录，不裁层、不挑文件；findPluginRoot 也改成递归定位，兼容「GitHub zip 带一层顶层目录」和「清单嵌在 ASS/ 里」两种布局。

2.3 交叉校验（crossCheck）

装载时三份声明互相核对，不一致直接拒绝并点名字段：

  • register.go.Name == plugin.json.name
  • Version / ProtocolVersion 一致（两边都非空时）
  • Hooks 集合完全一致（排序后逐项比较）—— 防止「JSON 里声明了但 Go 声明漏了」
  • Runtime / Home 一致

2.4 解释器探测：缺了就在装载时报

co.BEGG.requires 支持 php>=8.1 / python3 / node>=18 这类写法。宿主用 exec.LookPath 探测：

func (b *Begg) ProbeRuntime() (map[string]string, error)

缺解释器 → LoadContract(dir, true) 直接返回错误，点名缺哪个，不静默降级、不自动安装。安装阶段用 probe=false（允许先装后配环境），启用阶段 pluginset.loadOne 用 probe=true，也就是用户要求的「装载插件时直接报告」。

RuntimeBin 映射：php→php、python→python3|python、node→node、go→go、binary/external 不需要解释器。

3. 钩子：108 个，全部真接线

3.1 三档能力

档 业务侧调用 插件能做什么
通知 hooks.Emit(h, ctx) / plugin.FireIf 只收事件，不能拦、不能改
决策 hooks.Decide(h, ctx) / hooks.Gate(h, c, extras) 返回 deny → 宿主 403；DecisionOf 把含 blocked 的 error 归一成拒绝
变换 hooks.Mutate / hooks.DecideMutate 通过 CtxPatch 回写 ctx，业务侧读到被改后的值

实际生效的例子：

  • onUserQuotaChange：插件写 ctx.maxStorage 直接覆盖用户配额（controllers/file.go: effectiveMaxStorage）。
  • onFileUploadBefore：写 ctx.fileName 重命名、写 ctx.policyId 改存储策略。
  • onApiAuth：写 ctx.claims 注入身份信息。
  • onHealthCheck：写 ctx.healthy=false 让 /api/health 返回 503。

FireResult（进程外插件的 JSON-RPC 返回）：

{
  "ctxPatch": { "maxStorage": 999999 },
  "decision": "deny",
  "reason": "策略拒绝",
  "error": "",
  "log": []
}

host.dispatchSync 串行派发（后一个插件能看到前一个的写入），把 decision=deny 转成含 blocked 的 error，让 IsBlockedError / DecisionOf 对 v1 与 v2 插件行为完全一致。

进程内 Go 插件的 CtxPatch 同样生效：runHandler 会把 handler 返回的 map 合并回 ctx，支持直接返回 kv 或包一层 {"CtxPatch": {...}}。

3.2 同步策略：低频同步，高频走轻量门

用户把「同步范围」交给我定，落地规则是：

  • 低频决策点（登录、上传、删除、支付、备份…）用同步钩子，一次插件往返换来决定权。
  • 高频路径（下载、预览、权限校验、每次 API 请求）虽然标 ModeSync，但业务侧一律走 plugin.FireIf / hooks.Decide：先问 HasSubscribers，没有插件订阅时连 ctx 都不构造、零 IPC 往返。
  • 纯事件（onAuditLog、onNotificationSend…）异步通知，不等结果。

4. 注册型扩展点：插件提供实现，宿主来选

与「钩子」的区别：钩子是宿主在固定时机调用所有订阅者；注册型是插件声明「我能当某种后端」，宿主在需要时点名调用。

kind 默认钩子 用途
storage onStorageResolve 新存储后端（B2 / S3 兼容层）
auth onAuthProviderResolve 外部认证源 / SSO
notify onNotificationSend 邮件 / 短信 / Webhook 渠道
preview onFilePreview 接管在线预览
payment onPaymentCallback 支付渠道验签与开通
contentScan onContentScan 内容审核 / 查毒
backup onBackup 导出备份
restore onRestore 恢复数据
cli onCLI 自定义 CLI 子命令
search onStatsCollect 全文检索 / 统计数据源
theme onUIThemeApply 主题包
page onUIPageOpen 页面能力
ai onAIProviderResolve AI 模型提供方（智能时代新增，见第 14 节）

两种声明方式（可并存，Add 是追加语义）：

  1. co.BEGG 的 providers / plugin.json 的 providers 静态声明；
  2. 插件在 init 握手里通过 InitResult.Providers 动态上报。

业务侧调用 plugin.CallProvider(kind, name, ctx)；找不到注册项返回 nil，业务自行 fallback 到内置实现。

5. HTTP / HTTPS 页面插件

5.1 工作原理

宿主是 Go 单二进制，内部没有 PHP / Python 解释器。所以插件自己起 HTTP 服务，宿主只做三件事：

  1. plugin.AllocatePort() 分配一个本机空闲端口；
  2. 拉起 co.BEGG.command（或按 runtime 生成默认命令）并探活；
  3. 把 /ext/<plugin>/* 反代到 127.0.0.1:<port>。
浏览器 ── /ext/ass-demo/in.php ──> Gin ── ReverseProxy ──> 127.0.0.1:<port>/in.php (php -S)

RegisterRoutes 用 r.Any("/ext/:plugin/*path", s.Serve)，GET/POST/表单/上传全部透传。

pluginhttp.Serve 把目标路径放进 request.Context()，由 Start 时一次性设置的 Director 读取。不要在每个请求里改写共享 ReverseProxy.Director —— 那既是数据竞争，又会让闭包链无限增长。

5.2 0.0.0.0 规则

plugin.PublicHost(domain, boundIP) 按用户定的三条规则选对外主机名：

  1. 后台绑定了域名 → 用域名；
  2. 只绑定了 IP → 用 IP；
  3. 什么都没绑定 → 默认 127.0.0.1。

0.0.0.0 是通配绑定地址、浏览器无法访问，因此只作为「需要替换」的标记：ResolveExternalBase 用它生成对外 URL（siteURL 优先），而真实 socket 一律收紧到 127.0.0.1，插件端口不暴露公网。

前端还有一层兜底：frontend/src/store/pluginUI.ts 的 normalizePageURL 把 loopback / 同源绝对 URL 收敛成同源相对路径，保证无论站长用哪个域名访问，iframe 都能命中当前站点的 /ext/* 反代。

5.3 路径裁剪（php -S -t 的坑）

php -S ... -t ASS 启动后文档根已经是 ASS/。如果浏览器请求 /ASS/in.php，PHP 会去 ASS/ASS/in.php 找文件，必然 404。

Begg.PagePath(home) 负责把「相对 BeggDir 的路径」转成「相对文档根」的 URL 路径：

static home 生成的 URL 路径
ASS ASS/in.php /in.php
（省略） in.php /in.php
ASS ASS/sub/p.php /sub/p.php

pluginhttp.Start 把转换后的副本交给 GlobalRegistry.Add 生成侧边栏 URL；Serve 用同一个 rt.home 作为默认首页。原始 co.BEGG 声明不动，诊断接口仍按作者写的路径展示。

5.4 下发给插件进程的环境变量

变量 含义
NB_PLUGIN_NAME 插件名
NB_PLUGIN_DIR 插件安装根目录（Contract.Dir）
NB_PLUGIN_HOME 主页文件
NB_PLUGIN_SITE_URL 站点根 URL
NB_PLUGIN_PORT 宿主分配的端口
NB_PLUGIN_HOST 固定 127.0.0.1
NB_PLUGIN_PROTOCOL 当前协议版本

命令模板占位符：{port} {host} {dir} {entry} {home} {static}。runtime=php 的默认命令是 php -S {host}:{port} -t {static}。

5.5 外部页面与鉴权边界

  • runtime=external 或 listen 写 https://...：宿主不反代，/ext/<plugin>/* 直接 302 过去；前端对这类 URL 用新标签页打开（外部站点常有 X-Frame-Options）。
  • 宿主对 /ext/* 完全透传鉴权，插件自己负责登录与权限。宿主唯一门槛：全局开关已开 + 插件已启用，否则 404。
  • 宿主不注入 Bearer token（前端 token 存 localStorage），也不设 iframe sandbox。插件页面与宿主同源（反代），理论上能读宿主 cookie —— 这是「开启即授信任」的一部分，必须让站长在开启前看见。

6. UI 扩展点

前端是 React + go:embed，插件无法注入 React 组件，所以走声明式 + iframe + CSS 变量。

6.1 数据聚合

GET /api/plugins/ui 返回：

{
  "code": 0,
  "data": {
    "protocolVersion": 2,
    "globalEnabled": false,
    "sidebar": { "main": [...], "admin": [...] },
    "public": [...],
    "themes":    { "pluginName": { "name", "label", "css", "variables", "preview" } },
    "settings":  { "pluginName": [ { "key", "label", "type", "default", "options", "help" } ] },
    "providers": [...],
    "variables": {},       // onUIThemeApply 动态注入
    "dynamic":   {}        // onUIPageRegister 动态注入
  }
}

SidebarItem 字段：plugin / name / title / icon / area / role / order / embed / url / public。

area：main（主界面侧栏）、admin（后台侧栏）、public（主侧栏，无需登录语义由插件自定）；role：admin / user / any；embed：iframe（默认）/ newtab；icon 是 lucide 图标名，前端用白名单映射，未知名字回退 Puzzle。

主题应用只碰两个专属 DOM 节点（<style id="nebula-plugin-theme-style"> / <link id="nebula-plugin-theme-link">），切换时精确清理；CSS 变量名必须匹配 ^--[A-Za-z0-9_-]+$，值里出现 ; { } < > 或 url( 一律丢弃，防止插件借变量注入任意 CSS。

7. 默认关闭与风险确认（两道保险）

层 默认 位置
全局插件总开关 关 pluginset.InitPlugins 读开关，关时直接 return；pluginhttp.Global().SetGlobalEnabled(false)，/ext/* 一律 404
单插件 安装后默认 disabled 需在后台单独启用

开启总开关：

POST /api/admin/plugins/global
{ "enabled": true, "acknowledge": true }

后端 EnablePluginGlobal 强制要求 acknowledge=true，否则 400 并附上完整风险说明。前端 PluginRiskModal 在开启前弹出四条风险（进程权限、/ext/* 透传鉴权、数据泄露/入侵风险、宿主不审核第三方代码），必须勾选「我已知悉并自行承担」才能提交。

这条链路是「开放但不默认承担责任」的落点：代码默认关，站长自己开，开了概不负责。

后台还提供 GET /api/admin/plugins/contract/:name 诊断三文件契约与解释器，装载失败原因（缺哪个文件、缺哪个解释器、声明哪里不一致）直接可见。

8. 系统生命周期与 CLI

  • onBoot：bootstrap() 里 DB/迁移/JWT/插件宿主就绪后触发。
  • onShutdown：收到退出信号后、StopPlugins() 之前触发，插件可 flush 缓冲。
  • onScheduledTick：StartPluginScheduler() 每 5 分钟一次，顺带派发 onShareExpire / onPlanExpire，插件不必另起定时器。
  • onCLI：nebula hook <command> [args...]，插件把结果写进 ctx.output，宿主打印到 stdout。

server.py 从环境变量拿端口，用标准库起服务即可：

13. 已知限制与后续规划

  • 鉴权完全交给插件：/ext/* 同源反代、不注入 token、不设 iframe sandbox。插件若要识别当前用户，需自己实现（例如用一次性票据 + 宿主 onUIPageOpen 校验），宿主不代劳。这是站长已确认的取舍。
  • 插件进程权限 = 主服务权限：没有沙箱、没有 cgroup 限额、没有 CPU/内存配额。恶意插件可以直接读写服务器文件。
  • iptables / 端口：宿主把插件端口绑在 127.0.0.1，不暴露公网；但同机其他进程仍可访问该端口。
  • CSS 变量注入做了白名单过滤，但插件自带 ui.theme.css（通过 <link> 加载）仍是完整 CSS，等同于允许插件改整站样式 —— 属于「开启即授信任」的一部分。
  • 可视化插件制作器：已落地两个版本 —— 浏览器单文件 tools/plugin-builder.html 与 Python 桌面版 tools/插件制作器.py（21 套模板、首次启动新手教程、108 钩子选择器、拖拽 + 代码双模式、一键构建 ZIP）。后台内嵌版仍属后续规划。
  • /api/admin/stats/* 三个统计接口仍未实现（v1 遗留）；onStatsCollect 钩子已就位，可交给社区插件补数据，也可后续内置。

14. 智能时代：AI 钩子与 ai Provider

面向「让插件提供 AI 能力」的扩展。宿主内置智能搜索、近期常用、代码空间、AI 助手、摘要与自动标签，但不绑定任何模型厂商。完整插件写法见《插件制作手册》第 13 章。

14.1 三档降级

档 提供者 生效条件
L0 本地算法 宿主内置 永远（联想、近期常用、词法补全、提取式摘要）
L1 AI 网关 后台配置的 OpenAI 兼容端点 开启总开关 + 填了 key
L3 插件接管 订阅 onAIProviderResolve 或注册 kind=ai 插件启用

调用顺序固定为 插件 → 网关 → 本地，任一档不可用自动降级，因此没配模型时功能不会报错。

14.2 新增 9 个 AI 钩子（GroupAI）

onAIRequest（同步·可拦截·可变换，外发前改写 prompt 或 deny）、onAIResponse（异步通知）、onAIProviderResolve（注册型 ai，写 handled+result 接管）、onAIComplete（代码补全）、onAIRecommend（推荐覆盖）、onAISearch（自然语言检索条件覆盖）、onAISummary（摘要/标签接管）、onAIAsk（助手回答接管）、onAIConfigChange（配置变更通知）。

全部 Wired=true，静态扫描 108 个常量 / 0 个缺调用点。ProtocolVersion 仍为 2（v2 内增量，v1 插件零改动继续跑）。

14.3 新增 ai Provider

后台 → AI 设置 → 「能力提供方」下拉列出所有 kind=ai 注册项，选中后宿主用 CallProvider(ai, name, ctx) 点名调用，默认钩子 onAIProviderResolve。也可只订阅钩子、不注册 Provider，宿主同样会把 onAIProviderResolve 派发给订阅者 —— 两条路都能让社区插件完全替换模型。

14.5 边界

  • 站长选择「配置即用」时，文件名与代码片段会发给所选模型服务商；宿主不强制脱敏，但 onAIRequest 可改写 ctx.prompt 做插件侧脱敏。
  • 不希望出域：不填 key，用本地模型插件返回 result，或用 onAIRequest 直接 deny。
  • 代码空间默认关闭；开启后只接受 ≤ 2 MB 的 UTF-8 文本，保存走「新对象 + 版本归档 + 主记录更新」同一事务，避免秒传共享文件被误改。
