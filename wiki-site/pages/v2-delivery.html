插件平台 v2 —— 交付说明

本次接续上一轮「钩子不够多，改得尽量多、完全够用」的任务，把后端收尾缺陷、前端 UI 扩展点、后台管理界面、测试与文档全部落地并跑通验证。所有改动都在本地 clone 中完成，没有提交到 GitHub。

1. 本轮实际做了什么

A. 修掉 8 个真实缺陷（都是跑起来/测起来才暴露的）

# 缺陷 修法
1 pluginhttp.Serve 每个请求都改写共享 ReverseProxy.Director：并发数据竞争，且每次把上次 Director 包一层闭包，闭包链无限增长 Director 在 Start 时一次性设置，路径通过 request.Context() 传入，零共享可变状态
2 PHP 页面 URL 把 static 目录重复拼进路径（php -S -t ASS 下请求 /ASS/in.php → 404） 新增 Begg.StaticDir() / PagePath()；Start 用转换后的副本登记侧边栏 URL，Serve 用同一路径
3 install.InstallFromDir 仍按根目录读 plugin.json，findPluginRoot 只看一级，装不了「ASS/ 里放清单」的插件 改用 plugin.LoadContract 递归定位、整体复制源目录（不裁层）、findPluginRoot 递归
4 Manifest.Validate 无条件要求 entry，v2 纯页面插件在解析清单阶段就被拒，之前所有页面插件设计都落不了地 增加 purePageV2 例外：不订阅 hooks + 声明 pages 时可省略 entry
5 「v1 自动兼容」没做到底：宿主握手硬下发 HostProtocol=2，示例插件 referer-guard 校验 ==1 直接拒绝启动 新增 host.handshakeProtocol：对声明 v1 的插件，握手时宿主表现为 v1，老插件零改动
6 进程内 Go 插件的 CtxPatch 被 runHandler 丢弃，「变换」档只对进程外插件生效 runHandler 回写返回 map，兼容直接 kv 与 {"CtxPatch": {...}} 两种写法
7 verifyEntry 只认 plugin.json 的 pages，页面只写在 co.BEGG 的插件被误判缺 entry 用 contract.Begg.Pages 一起判断
8 ValidateFiles 把 JSON-RPC entry 当页面文件按 BeggDir 校验，误判「可执行文件在根、co.BEGG 在子目录」的合法布局 只校验 home / static，entry 交由 ExecPath 按插件根目录解析

第 5 条是全量 go test ./... 才暴露的：之前只跑 go build 看不到。这也说明为什么这轮一定要把测试跑绿。

4. 使用提醒（重要）

  • 插件系统默认关闭：全局总开关 + 单插件双保险。开启总开关必须走免责弹窗，后端强制 acknowledge=true。
  • /ext/* 完全透传鉴权：插件自负责登录与权限，宿主不注入 token、不设 iframe sandbox。插件页面与宿主同源（反代），理论上能读宿主 cookie —— 这是「开启即授信任」的一部分。
  • co.BEGG 里的相对路径基准是 co.BEGG 所在目录，不是插件根目录。把 co.BEGG 和 in.php 一起放进 ASS/，home 写 "in.php" 即可；register.go 与 co.BEGG 的 Home / home 必须字面一致。
  • 缺解释器时装载阶段直接报错，不自动安装、不静默降级。

5. 仍未做 / 后续规划

  • 可视化插件制作器：你提的「正式版以后做」，本次未实现；当前靠三文件契约 + 后台诊断降低试错成本。
  • /api/admin/stats/* 三个统计接口（v1 遗留）仍未内置；onStatsCollect 钩子已就位，可交给社区插件补数据。
  • i18n 的繁中 / 日 / 韩三种语言暂走 fallbackLng: 'zh-CN'，需要完整本地化时再补。
  • 插件进程没有沙箱 / 资源配额，权限等同主服务；这是已确认的取舍，若要收紧需单独做隔离层。
