站点部署与运维手册

本文记录 2026-11-08 起在 Debian 11 服务器上的实战部署结果，并同步后续域名、本地模型、插件市场三项演进，供后续维护参考。 出于安全考虑，本文不包含任何密码、令牌明文；凭据统一存放在服务器本地文件中。

一、站点与服务一览

站点 端口 监听范围 用途 服务
NebulaDrive 网盘 80 0.0.0.0 主站，文件存储与分享 nebuladrive.service
源站 TLS 终止 443 0.0.0.0 Cloudflare Full 回源 nebula-tls.service
智能 AI 工单站 8081 0.0.0.0 提交问题、智能答复、跟进 ai-desk.service
项目 Wiki 8082 0.0.0.0 文档、手册、变更记录 wiki.service
本地模型网关 8083 仅 127.0.0.1 OpenAI 兼容 /v1/chat/completions llm-local.service
官方插件商店源 8084 仅 127.0.0.1 com.json + .pbclus 静态源 plugin-store.service

六个服务均已设置开机自启（systemctl enable），失败自动重启。

8083 / 8084 只绑回环，是刻意的：模型网关与插件包只允许本机进程访问，不对外开门。

数据目录：网盘 /var/lib/nebuladrive、工单站 /opt/ai-desk/data、Wiki /opt/wiki、模型 /opt/llm、插件商店 /opt/plugin-store。

服务器环境：Debian 11 / 2 核 / 1.9 GiB 内存 / 40 GiB 磁盘。

二、常用运维命令

# 全部服务状态
systemctl status nebuladrive nebula-tls ai-desk wiki llm-local plugin-store --no-pager

# 重启

systemctl restart llm-local

# 日志
journalctl -u nebuladrive -f

# 健康检查

四、当前已生效的核心设置

1. 每用户 1 GB 空间

配额落在 default 用户组（max_storage = 1073741824 字节）。新用户默认归属该组且 plan_id = 0，因此有效额度为 1 GB。

安装时系统会自动创建三档付费套餐（Ultra / Pro / Pro Max），套餐额度优先于用户组额度。若日后分配套餐，1 GB 会被覆盖。

修改方式：后台 管理 → 用户组 → default → 最大存储，或 API：

TOKEN=<管理员登录后取得的 JWT>
curl -X PUT http://127.0.0.1/api/admin/groups/1 \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"default","maxStorage":1073741824,"shareEnabled":true,"webdavEnabled":true,"speedLimit":0}'

2. 邮箱注册（待配置）

当前状态：未启用，等你提供邮箱信息后再填。 待填字段：SMTP 主机/端口、发信账号与授权码（不是登录密码）、发件人、mail.enabled = true。配置入口：后台 管理 → 设置 → 邮件。启用后可用于找回密码、注册验证、通知邮件。

3. 注册限制：只允许登录

当前状态：公开注册已关闭，security.allow_register = false。未登录调用注册接口返回 403 {"message":"未开放注册"}，登录接口正常。代码依据：controllers/auth.go 的 getSettingBool("security.allow_register", false)，默认即拒绝。

# 关闭注册（当前配置）
curl -X POST http://127.0.0.1/api/admin/settings \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"security.allow_register":"false"}'

注册码能力：已由官方插件提供

项目本体没有内置注册码，但官方插件 nd-invite-code 已上架（见《官方插件市场与插件清单》），订阅 onAuthRegisterBefore 决策钩子：

  1. 在后台插件商店安装并启用该插件；
  2. 在插件配置里填 {"codes": ["BERRY-2026"]}，或在插件数据目录放 codes.txt（一行一个码）；
  3. 把 security.allow_register 临时改为 true，由插件把关；
  4. 未填或填错注册码一律被拒绝。

未配置任何码时插件自动放行，不会一装上就锁死注册。此增强默认未启用。

五、域名与 HTTPS

域名 cloud.berrywing.top 已接入 Cloudflare，回源模式为 Full。当前链路：

浏览器 --HTTPS--> Cloudflare --HTTPS(443)--> nebula-tls.service(socat,自签证书)
                                              └--HTTP--> 127.0.0.1:80 --> NebulaDrive
  • /var/lib/nebuladrive/conf.ini：domain = cloud.berrywing.top、protocol = https、listen = 0.0.0.0:80、tlsMode = off
  • 源站 443 由 nebula-tls.service 用 socat + 自签证书终止 TLS，再转发到本机 80
  • 自签证书：/var/lib/nebuladrive/ssl/cert.pem、key.pem

为什么用自签：Cloudflare Full 模式只要求源站有 HTTPS，不校验源站证书链，因此自签即可工作，且不需要在源站开放 80 挑战端口。建议后续换成 Cloudflare Origin CA 证书（15 年有效期，Cloudflare 可信任），替换两个 pem 后 systemctl restart nebula-tls 即可。

若改用项目内置 ACME：把 tlsMode 设为 auto、停掉 nebula-tls.service，让程序自己申请证书。

关于 8081 / 8082 端口：这两个站点目前仍走 http://<IP>:8081 / :8082。如需统一到域名，可在 Cloudflare 加子域名并用 Nginx 反代，或直接把它们收敛到回环 + SSH 隧道访问。

六、本地模型与 AI 工单站

运行时

服务器上没有可用的预编译 llama.cpp 二进制，且 GitHub Release 直连与多个镜像均失败。最终方案是从 PyPI 拉 llama-cpp-python 的 sdist（65 MB，内含完整 vendor/llama.cpp 源码），在服务器本地用 gcc/g++/cmake 编译：

# 关键前置：Debian 11 需要 git（CMake 用它生成 build-info）
apt-get install -y git
pip3 install --no-binary :all: llama-cpp-python==0.3.9   # 源码编译

产物是 glibc 版 llama_cpp_python-0.3.9-cp39-cp39-linux_x86_64.whl。此前尝试的 0.3.19 预编译 wheel 是 musl 构建，在 Debian glibc 上会报 libc.musl-x86_64.so.1: cannot open shared object file，已弃用。

模型与网关

项目 值
模型文件 /opt/llm/model.gguf（Qwen2.5-0.5B-Instruct Q4_K_M，约 469 MB）
网关源码 /opt/llm/llm_server.py（Python 标准库 + llama_cpp）
监听 仅 127.0.0.1:8083，MemoryMax=900M
接口 POST /v1/chat/completions、GET /v1/models、GET /health

网关把模型常驻内存、用锁串行化推理（2 核小机更稳），并截断超长输入与限制 max_tokens。工单站通过 deskctl.py 配置为 base_url = http://127.0.0.1:8083/v1、enabled = true。详见《智能 AI 工单站使用说明》。

八、数据备份

mkdir -p /root/backup
tar czf /root/backup/nebula-$(date +%F).tar.gz \
  /var/lib/nebuladrive \
  /opt/ai-desk/data /opt/ai-desk/config.json \
  /opt/plugin-store /opt/wiki
  • secret.key 必须一起备份，否则加密配置无法解密
  • 上传文件位于 /var/lib/nebuladrive/uploads，数据量大时单独做增量同步
  • 模型文件 /opt/llm/model.gguf 可随时重新下载，不必每日备份
  • 官方签名私钥在构建机上离线保管，单独备份，绝不放进服务器归档
  • 恢复时先停服务，解压覆盖，再启动

十、故障排查速查

现象 排查方向
网盘打不开 systemctl status nebuladrive → journalctl -u nebuladrive -n 100；确认 80 端口未被占用
域名 HTTPS 报 525 / 521 检查 nebula-tls.service 是否在跑、443 是否监听、证书路径是否正确
上传提示空间不足 检查 default 组配额与用户已用量；确认是否被套餐覆盖
无法注册 属预期行为（已关闭注册）；需管理员创建用户，或启用 nd-invite-code 注册码插件后临时开放
邮件发不出 检查 SMTP 主机/端口/授权码；当前未配置属正常
工单答复变成「本地模型暂不可用」 systemctl status llm-local、curl 127.0.0.1:8083/health；此时工单已自动回退知识库，不会丢单
工单站看不到管理入口 属预期行为；用 deskctl.py url 获取隐藏地址
后台插件商店为空 检查 plugin.store.url 设置、plugin-store.service 状态、curl 127.0.0.1:8084/com.json
插件启用报 hooks 类型错误 插件 init 响应里 hooks 必须是 JSON 数组而不是字符串
Wiki 页面 404 确认 wiki.service 运行、/opt/wiki 下存在 index.html
