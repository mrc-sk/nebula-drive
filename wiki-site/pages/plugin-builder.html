Python 桌面版：拖拽控件、21 套模板、首次教程

插件制作器 · Python 桌面版 使用说明

一个用 Python 标准库 tkinter 写的原生窗口程序。Windows / Linux / macOS 都能跑， 不装第三方包、不联网、单文件。生成物对齐 NebulaDrive 插件协议 v2 三文件契约。

1. 怎么启动

系统 做法
Windows 双击 启动-Windows.bat（或直接 python 插件制作器.py）
Linux / macOS ./启动-Linux.sh（或直接 python3 插件制作器.py）

依赖只有 Python 3.8+ 和 tkinter：

  • Windows：官网安装包自带 tkinter，安装时勾选 Add Python to PATH 和 tcl/tk and IDLE。
  • Linux：多数发行版预装；缺的话 sudo apt install python3-tk（Fedora 用 python3-tkinter，Arch 用 tk）。

第一次启动会自动弹出 6 步新手教程，看完点「开始使用」即可；以后从「帮助 → 新手教程」重看。 想恢复首次体验，删掉用户主目录下的 .nebuladrive_plugin_builder.json。

2. 界面五个页签

页签 干什么
① 设计 左侧控件库单击或拖拽到中间画布；点卡片在右侧改属性；↑↓ 排序、✕ 删除。顶部三个固定项：插件身份 / 运行时 / 目录布局
② 代码 直接编辑每个生成文件；改动自动写回工程。「重置为自动生成」「同步回设计」可双向切换
③ 校验 模拟宿主 ParseManifest / ParseBegg / crossCheck / ValidateFiles，红字会阻止构建
④ 构建 预览目录树和每个文件内容，导出 ZIP 或导出到目录
⑤ 页面预览 用原生控件模拟网盘里的插件页面（侧边栏 + 控件），也能在浏览器打开完整 HTML

两种画布：「结构画布」放页面 / 设置字段 / 主题 / 注册型能力 / 钩子订阅；「页面画布」放标题 / 卡片 / 统计 / 表格 / 按钮等页面控件。 「钩子订阅」控件会打开 99 个钩子选择器，可搜索、可批量勾选。

3. 21 套内置模板（≥ 15 套要求）

分组 模板
入门 3 空白最小工程、Hello 面板（PHP）、ASS/ 子目录布局
页面与运行时 6 Python 数据看板、Node.js 面板、Go 标准库 HTTP 服务、纯静态站点、外部 HTTPS 页面、后台管理控制台
主题与 UI 2 海洋蓝主题包、UI 全家桶
钩子 / JSON-RPC 5 上传守卫（决策型）、请求 WAF、全量审计日志、配额变换（ctxPatch）、Node.js 钩子插件
注册型能力 3 自定义存储后端、自定义通知渠道、备份与恢复扩展
AI 场景 2 AI 助手页面、AI 内容审核

每套都能一键构建并被宿主装载。左上模板下拉或「模板库」菜单切换。

4. 三步做一个插件

  1. 选模板 → 在「设计」页拖控件、改属性（或在「代码」页写 PHP / Python）。
  2. 「③ 校验」全绿 → 点右上「一键构建 ZIP」。
  3. 解压到 plugins/<插件名>/ → 后台开启全局总开关（勾选风险确认）→ 启用插件。

插件默认关闭是刻意设计；宿主对 /ext/* 完全透传鉴权，插件页面必须自己鉴权。 缺 PHP / Python / Node 等解释器时，宿主会在启用时明确报错，不静默降级。

5. 命令行自检（无桌面环境也能用）

python3 插件制作器.py --selftest          # 21 套模板：生成 + 校验 + ZIP CRC + 导出目录
python3 插件制作器.py --gui-check         # 虚拟显示器下跑 94 项 GUI 交互自检
python3 插件制作器.py --build-all DIR     # 批量导出 21 套模板到 DIR，供联调
python3 插件制作器.py --smoke             # 窗口冒烟，2 秒后自动退出

--selftest 已覆盖 21/21 模板；产物另经宿主 Go 代码 LoadContract、InstallFromDir、InstallFromZip 全量验证 21/21 通过。

6. 三文件契约速记

文件 作用
plugin.json 我是谁、我要什么（身份 / 钩子 / 页面 / 注册型能力）
register.go 把同样的话用 Go 字面量再说一遍，宿主只读不编译，服务器不用装 Go
co.BEGG 怎么跑起来、长什么样（runtime / requires / home / pages / ui）
  • 三个文件可在任意子目录（ASS/ 也行），宿主递归定位，深度 ≤ 5。
  • 路径基准是 co.BEGG 所在目录：home 写 in.php，不要写 ASS/in.php。
  • 三份声明互相核对（name / version / protocolVersion / hooks / runtime / home），不一致直接拒绝装载。

7. 附录：让 AI 帮你写插件时的要求模板

如果你想把「做一个插件」这件事交给 AI，可以直接复制下面这段，避免它写出宿主装不上的东西：

请帮我做一个 NebulaDrive v2 插件，要求： 1. 必须包含 plugin.json、register.go、co.BEGG 三个文件；register.go 只是 Go 字面量声明，不要写需要编译的代码。 2. plugin.json 的 protocolVersion 为 2，hooks/pages/providers 不可三者皆空；钩子名必须来自宿主 99 个钩子表。 3. register.go 与 plugin.json 的 Hooks 集合、以及 Name/Runtime/Home 必须完全一致。 4. co.BEGG 的 runtime 只能是 php/python/node/go/binary/external；requires 写明解释器；home/static 用相对 co.BEGG 所在目录的路径，不含 ..。 5. 目录形式不限，ASS/ 子目录布局也可以；不要写 ASS/in.php 这种带前缀的路径。 6. 订阅了钩子就要提供可执行的 entry（单个文件名），并给出 Python 或 Node 的 JSON-RPC over stdio 骨架，日志走 stderr。 7. 插件页面自己鉴权（宿主对 /ext/* 完全透传），并把用到的 NB_PLUGIN_* 环境变量说明清楚。 8. 附带 README：安装步骤（开全局总开关 → 启用单插件）、默认关闭说明、安全提醒。 9. 优先参考现成模板：入门 / 页面与运行时 / 主题与 UI / 钩子 / 注册型能力 / AI 场景，共 21 套，选最接近的一套改。 10. 生成后自查：JSON 严格字段白名单、无未知字段、home 文件真实存在、三文件交叉一致。

8. 常见问题

  • 装了插件没反应：先去后台开启全局总开关，再启用单个插件。
  • 提示缺少解释器：服务器没装对应解释器，装上再启用；宿主不会自动安装。
  • Linux 下打不开窗口：缺 python3-tk，见第 1 节。
  • 代码页改了没生效：改动会自动写回；想丢弃手工内容点「重置为自动生成」。
  • 构建被阻止：去「③ 校验」看红字，最常见是 home 文件缺失或钩子两边不一致。
