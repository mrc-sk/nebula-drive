官方插件市场与插件清单

2026-11-08 上架 10 个官方插件，全部为 v2 三文件契约的 Python 纯钩子插件，由官方 Ed25519 密钥签名。

一、市场架构

后台「插件 → 商店」
   └─ 后端读 plugin.store.url = http://127.0.0.1:8084/
        └─ GET /com.json  → 10 条清单
   └─ 点「安装」
        └─ 后端 GET /<name>.pbclus → 校验签名 + 契约 → 解压到 /var/lib/nebuladrive/plugins/<name>
   └─ 点「启用」→ 宿主拉起 JSON-RPC 子进程 → init 握手
部件 位置
静态源目录 /opt/plugin-store（com.json + 10 个 .pbclus）
静态服务 plugin-store.service，python3 -m http.server 8084 --bind 127.0.0.1
信任库 /var/lib/nebuladrive/plugin-trust.json（只含公钥）
商店地址 后台设置 plugin.store.url
构建工具 本地 backend/cmd/ndtools（契约校验 / 签名打包 / 回读校验）

包格式是 PBClus v2（.pbclus），签名算法 Ed25519，平台标签 any（纯 Python，无原生二进制）。签名状态三态 present / valid / trusted 全为 true；数据库 plugins.trusted = 1。

商店源只绑回环：清单与包都由网盘后端拉取，前端不直连 8084，公网无需开放。

签名策略当前为默认 warn。若希望只装官方签名包，可在后台把 signatureMode 设为 require；注意这会让所有存量未签名插件装不上，需先确认。

二、10 个官方插件

# 插件名 标题 订阅钩子 类型 作用
1 nd-invite-code 注册邀请码 onAuthRegisterBefore 决策 校验注册码，补上项目缺失的邀请码能力；未配置码表时自动放行
2 nd-upload-guard 上传安全守卫 onFileUploadBefore 决策 拦截可执行文件/脚本扩展名、路径穿越文件名，可限制单文件大小
3 nd-filename-clean 文件名规范化 onFileUploadBefore、onFileRename 变换 清洗非法字符、路径片段，截断过长文件名
4 nd-quota-watch 配额用量预警 onFileUploadAfter、onUserQuotaChange 通知/变换 用量超过阈值（默认 80%）时注入预警并记日志
5 nd-login-brake 登录爆破抑制 onAuthBeforeLogin、onAuthLoginFailed、onAuthLoginSuccess 决策 同 IP/账号短时连续失败后临时锁定（默认 60s/5 次/锁 300s）
6 nd-share-policy 分享链接策略 onShareCreateBefore 决策/变换 强制分享带密码，未设有效期时自动补 7 天，避免永久裸链
7 nd-audit-trail 关键操作审计 onFileUploadAfter、onFileDelete、onAuthLoginSuccess、onShareCreateAfter、onUserDelete 通知 关键事件写 audit.log（JSONL，落插件数据目录）
8 nd-webdav-guard WebDAV 写保护 onWebDAVPut、onWebDAVDelete 决策 可切只读、禁删、保护指定路径前缀；默认完全放行
9 nd-sensitive-tag 敏感文件标记 onContentScan、onFileUploadAfter 变换 关键词命中时打 sensitive=true 与「需复核」标签，不拦截
10 nd-maintenance 维护模式与站点公告 onRequestBefore、onUIPageOpen 决策/变换 放置标志文件后进入维护模式（管理员放行），并向页面注入公告

设计取舍

  • 全部是纯钩子插件：co.BEGG 只声明 runtime / requires，不写 pages / command，因此不会启动任何 HTTP 页面服务，不占用额外端口。
  • 默认宽松，不误伤：所有插件在未配置时要么放行、要么只记录日志。装了不会立刻改变站点行为，需要管理员显式配置或放置标志文件才生效。这符合「开启插件前免责」的设计。
  • 零外部依赖：只用 Python 3 标准库（json / os / sys / time），服务器无需额外 pip 包。
  • stdout 只走 JSON-RPC，日志通过返回的 log 字段交给宿主，绝不 print 调试信息污染分帧。

三、安装、启用与配置

  1. 后台 插件 → 商店 → 找到插件点「安装」。安装成功后提示「需要点击『启用』才会真正加载」。
  2. 首次启用前需阅读并接受插件免责协议（后台 /api/admin/plugins/agreement）。本次部署已接受。
  3. 点「启用」→ 宿主拉起子进程并完成 init 握手，状态变为 running。
  4. 需要策略的插件，在 插件 → 配置 里填 JSON，对应 plugins.config，会在 init 时下发。

常用配置示例：

// nd-invite-code
{"codes": ["BERRY-2026", "TEAM-ONLY"]}

// nd-upload-guard
{"blockedExtensions": [".exe", ".sh", ".php"], "maxBytes": 524288000}

// nd-share-policy
{"requirePassword": true, "forbidPermanent": true, "defaultDays": 7}

// nd-webdav-guard
{"readonly": false, "forbidDelete": false, "denyPaths": "/系统,/归档"}

nd-invite-code 也可在插件数据目录放 codes.txt（一行一个码，# 注释）。nd-maintenance 用数据目录下的 maintenance.flag 文件内容作为公告文案，删除即恢复。

五、二次开发：如何新增/更新官方插件

本地构建产物在 /workspace/official-plugins/：

build_plugins.py            生成 10 个插件目录（三文件契约 + plugin.py + README）
plugins/<name>/             插件源码
store/                      com.json + 签名 .pbclus + plugin-trust.json
official-signing-key.json   官方私钥（0600，离线保管）

cd /workspace/nebula-drive-plugin-v2/backend
go run ./cmd/ndtools -store-url http://127.0.0.1:8084/ verify  # 契约校验
go run ./cmd/ndtools -store-url http://127.0.0.1:8084/ pack    # 签名打包 + 清单 + 信任库
go run ./cmd/ndtools check                                      # 回读校验签名

打包后把 store/ 里的 com.json 与 .pbclus 同步到 /opt/plugin-store/ 即可（静态服务无需重启）。复用同一个密钥文件，否则已加入信任库的 keyId 会失效，需要同步更新服务器上的 plugin-trust.json。

踩过的坑（写给后来者）

坑 说明
init 的 hooks 必须是数组 宿主 InitResult.Hooks 是 []string；写成字符串会在启用时报 cannot unmarshal string into Go struct field InitResult.hooks
entry 需要可执行位 宿主用 exec.Command(<插件目录>/<entry>) 直接拉起，所以 plugin.py 要有 #!/usr/bin/env python3；安装器 copyTree 会统一写 0750
三文件 hooks 必须一致 plugin.json 与 register.go 的 Hooks 集合会被 crossCheck 逐个比对
纯钩子插件别写 pages co.BEGG 里出现 pages 会让宿主按页面插件启动 HTTP 服务
私钥不要上服务器 服务器只需公钥信任库；私钥泄露等于任何人都能签「官方包」

六、注意事项

  • 插件以子进程运行，拥有宿主同等的文件与网络权限。安装前看清权限声明，启用前先读免责协议。
  • signatureMode 默认 warn：未签名包也能装（会有告警）。要严格锁定官方来源请改成 require。
  • 插件配置改动后需重启插件（后台「重启」按钮）才会重新 init 下发新配置。
  • 每个插件的详细配置字段见其 README.md（打包在 .pbclus 内，安装后位于插件目录）。
