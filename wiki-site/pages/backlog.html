2. 逐项详情

2.1 smtp-email —— 把邮件真正发出去 —— ✅ 已完成

已实现：net/smtp 三种 TLS 模式（starttls/implicit/none）、 中文主题 RFC 2047 编码、中文正文 base64、ASCII 正文 7bit、 头注入防护（剥离 CR/LF）、SMTP AUTH（服务器未声明 AUTH 时明确报错）、 配置不全时 fail closed、密码脱敏。

与本节原计划的差异：

  • 原计划第 3 条"失败记录落 DataDir"没有做 —— 失败信息走宿主日志 环形缓冲即可，落盘还要担磁盘被写满的风险。因此 plugin.json 里 原本声明的 write-own-datadir 权限已删除：声明用不到的权限会 高估插件所需权限，而管理员正是靠这份声明判断风险。
  • 端到端不是用 aiosmtpd，而是在 Go 里写了个最小 SMTP 服务器 （见下面三层测试），这样能进 CI、无外部依赖。

三层测试（字段名是宿主与插件两个 module 之间的约定，改名没有编译错误）：

层 覆盖
controllers/notification_email_test.go 宿主侧：CreateNotification 真的触发 onEmail，字段名与内容正确；无邮箱时不触发
examples/plugins/smtp-email/main_test.go 插件侧：假 SMTP 服务器真实协议往返，8 个用例
pkg/plugin/host/smtp_email_e2e_test.go 完整链路：宿主下发配置 → 子进程 → net/smtp → 假服务器 → 断言报文

单测抓出的实现 bug：base64 路径漏了 CRLF 归一化（收件人会拿到 LF 行尾， 违反 RFC 5321）。断言 正文解码后应等于 toCRLF(原文) 当场抓出，改的是实现。

反向验证：把插件的 ctx["to"] 改成 ctx["recipient"] 后， 端到端测试 1.02 秒内精确报出"字段名约定断了"（第一版要 16 秒才失败且 报的是超时，会被误判成网络问题）。

遗留：SMTP 抖动时的失败重试与退避尚未实现。当前失败即记 warn； 宿主每次创建通知都会重新触发，所以"下一封"会自然重试。

2.2 onAntiLeech 覆盖公开分享下载 —— ✅ 已完成

原缺口：onAntiLeech 全项目只有一个调用点（controllers/file.go）， 公开分享走 controllers/share.go 的 serveShareFile，完全不触发该钩子 —— 装了防盗链插件的站点，分享链接依然可以被任意第三方站点盗刷。

实际实现（与本节原计划的差异，均已写进注释说明理由）：

  • 调用点落在 target 解析并通过祖先链校验之后、handlerForFile(&target) 之前。
  • 拦截判定复用 plugin.IsBlockedError。
  • download 与 preview 都过闸。原计划里我把"预览要不要拦"留作待决定的取舍， 实现时实测发现：preview 虽然用 inline，返回的仍是完整文件内容， 只拦 download 就是留了一条完整的 exfil 通道。反向验证直接打出了证据： share_antileech_test.go:126: 分享**预览**未被防盗链拦截: status=200 body=hello share 所以宿主对两者一视同仁，把取舍通过 shareKind 交给插件。
  • ctx 契约最终为： {userId(恒为0), userName(恒为空), ip, ua, fileId, fileName, referer, shareId, shareKind, shareOwnerId}。 userId 键必须存在（键缺失与"存在且为 0"是两种语义）；分享所有者另放 shareOwnerId，避免与"访问者"混淆。

验证：3 个包级测试（下载/预览拦截、无插件零回归、非 blocked 错误不拦截） + 两次反向验证（全部各自 FAIL）+ smoke_plugin.sh 26/26 端到端。 详见 FIXLOG §20。

行为变更提示：装了防盗链插件的站点，分享链接现在也会被判定。 本站分享页会带自身 Referer，正常配置下命中白名单；只想保护下载的插件 请按 shareKind 自行放行。

onApiAuth ✅ 已完成

计划被推翻的一点：原计划写"照 onRateLimit 加同步门"，但那个前提不成立 —— onRateLimit 有 7 个调用点、只有 1 个要读结果，才需要单独开门； onApiAuth 只有一个调用点且必须读结果，所以直接把它本身改成 ModeSync + Blockable: true 即可，不需要任何额外的门。 教训：照抄某个模式之前，先核对前提是否相同。

实现要点：

  • 调用点：middleware/api_auth.go，PAT / OAuth2 都失败之后才触发 （热路径零成本 + 内置凭据优先，插件无法否决有效令牌）。
  • 放行：插件写 ctx["principalUserId"]；拒绝：返回含 blocked 的 error（403）； 两者都没有 → 401（fail closed）。
  • ctx 契约见 hooks.go 的钩子文档。两处刻意设计： headers 不含 Authorization（内置凭据留在宿主）； bodyHash 有 64KB 上限且会把已读字节放回请求流（下游仍能读到完整 body）。
  • principalUserId 必须兼容 int/uint/float64 —— 进程外插件回写经 JSON 往返后是 float64，只认一种会静默无法放行。

验证：7 个包级用例 + 2 次反向验证（"没表态当成放行" 与 "忽略 blocked" 都各自 FAIL）+ smoke_plugin.sh 第 8 节真机端到端（30/30）。

配套插件：examples/plugins/hmac-auth/ 的契约清单已修正 —— 占位阶段写的 timestamp/signature/appKey 等字段宿主根本不发， 它们是插件应自己从 ctx["headers"] 取的凭据头。该插件仍是探针， 当前不会放行任何请求。

onBackup / onRestore ✅ 已完成

  • 新增 POST /api/admin/backup：生成 zip（nebula.db + manifest.json）， 生成之后触发 onBackup（异步通知，插件据此复制到 S3/异地或落审计）。 MySQL/PG 不做库文件备份（拿不到一致快照），响应里明说。
  • 新增 POST /api/admin/backup/restore（挂 RequireConfirm）：暂存制。 校验 SQLite 文件头后写进 data/restore/ + PENDING 标记， 真正的替换发生在下次启动（ApplyPendingRestore 在 db.Init 之前）。 热替换正在使用的 SQLite 库会损坏数据，这不是保守而是唯一安全做法。 原库改名保留（.pre-restore-<ts>），挪不动就放弃、不硬覆盖。
  • GET /api/admin/backup/download?name=：名字来自查询参数， 字符集校验 + 解析后前缀校验双保险（8 种穿越形状都有测试）。

onCLI ✅ 已完成

  • 新增 nebula plugin <cmd> [args...] 子命令，放在 flag.Parse 之后 （全局参数如 -data 在子命令里照常可用）。
  • onCLI 是 ModeSync + Blockable（命令行必须拿到输出）： 插件写 cliOutput（打印）与 cliExitCode。 退出码约定 0 成功 / 1 用法错误或被拒 / 2 未安装。
  • 子命令不启动 HTTP 服务（冒烟里有断言）。

2.4 hmac-auth —— ✅ 已完成

已实现：HMAC-SHA256 校验、常量时间比较（hmac.Equal）、 时间窗防重放、exemptPaths 路径段匹配、bodyTruncated 拒绝、 配置不全时 fail closed、日志脱敏。

规范串：METHOD\nPATH\nQUERY\nTIMESTAMP\nBODY_SHA256_HEX，五行缺一不可。

实现过程中发现的真 bug（只有端到端能抓到）： 签名请求一直返回 401，而插件进程在跑、钩子计数也对、插件日志却一片空白。 根因是 APIAuth 在 tok == "" 时提前 401 返回，而 HMAC 客户端 根本不用 Authorization 头 —— 扩展鉴权永远收不到这类请求， 且那个 401 看起来完全正常。已修（把早退改成最后兜底）并补了回归测试。 详见 FIXLOG §23。

验证：插件单测 7 项篡改表 + 时间窗 + fail closed + 免签边界； pkg/plugin/host 真实子进程端到端 4 例；smoke_plugin.sh 第 8 节 真实 HTTP 签名（有效 200 / 篡改 403 / 缺签名 403 / 过期 403），36/36。

遗留：principalUserId 只支持单一身份 —— 多个调用方需要各自身份时， 得按 appKey 映射到不同用户。

6. 实现时遵守的既有约定（后续维护也要）

这些约束在本轮实现中都被遵守，改动插件相关代码时仍适用：

  1. 拦截只认字符串：strings.Contains(err.Error(), "blocked")（大小写敏感）， 唯一实现是 plugin.IsBlockedError。不要在业务代码里再写一遍判定。
  2. Mode 由实际触发点决定，不是设计意图：onRateLimit 的 "整体异步 + 个别处同步门"、onApiAuth/onCLI 的纯同步， 都是被"有几个调用点、要不要读结果"逼出来的。 照抄某个模式之前先核对前提是否相同（§22 就是照抄失败的一次）。
  3. Fire 不持锁执行用户代码，Register/List 不能被 IPC 往返卡住。
  4. 未接入的钩子不许假装可用：管理端靠 wired/planned 两个正交字段 如实展示。现在 Hooks 表里已无 Wired:false，但仍要守住 "标了 Planned 就必须有 Plan"的不变量（TestHookPlanMetadata）。
  5. main.go 的启动顺序：ApplyPendingRestore（备份恢复，在 db.Init 之前）→ db.Init → pluginset.InitPlugins → migrations.Run。 onDBMigrate 在迁移内部触发，顺序错了会错过本次。
  6. 写加密字段必须包 models.Encrypted(...)：driver.Valuer 只对 带类型的值生效，传裸 string 会明文落库且没有任何报错（§17、§24）。
  7. 跨进程的数字类型要兼容 float64：进程外插件的回写经 JSON 往返后 都是 float64；只认 int/uint 会让功能静默失效（§22、§25）。
