从零做一个插件：三文件契约、钩子、打包与调试

NebulaDrive 插件制作手册

面向：想给 NebulaDrive 写插件的人（不需要懂 Go，也不需要装 Go）。 协议版本：v2（宿主同时兼容 v1）。 配套工具：插件制作器.py（Python 桌面版，Windows / Linux / macOS 通用，推荐） 或 插件制作器.html（浏览器版单文件）。均为图形化拖拽 / 写代码双模式，一键构建出可安装的插件目录。 协议参考（偏底层、想深挖时再看）：仓库内 docs/插件平台v2-完全指南.md。

0. 先记住这 5 条

# 规则 违反的后果
1 插件默认关闭：全局总开关默认关、单插件装完默认关 装了没反应，先去后台开总开关
2 v2 插件必须有 3 个文件：plugin.json、register.go、co.BEGG 缺一个就装不上，报「缺少 xxx」
3 三个文件可以放在任意子目录（ASS/ 里也行），宿主递归找，深度 ≤ 5 不用纠结目录长什么样
4 路径基准是 co.BEGG 所在目录，不是插件根目录 home 写成 ASS/in.php 会 404，要写 in.php
5 开启插件 = 把服务器执行权限交给插件作者；宿主对 /ext/* 完全透传鉴权 只装你信任的插件

一句话心智模型：plugin.json 说「我是谁、我要什么」，register.go 把同样的话用 Go 字面量再说一遍，co.BEGG 说「怎么跑起来、长什么样」。 三份声明会互相核对，不一致直接拒绝装载。

1. 快速上手（3 分钟，两个办法）

办法 A：用可视化制作器（推荐）

A1 · Python 桌面版（跨平台窗口，推荐）

  1. Windows 双击 启动-Windows.bat；Linux/macOS 运行 ./启动-Linux.sh（或直接 python3 插件制作器.py）。 需要 Python 3.8+ 与 tkinter；Windows 安装包自带，Linux 缺的话 sudo apt install python3-tk。
  2. 第一次启动会自动弹出 6 步新手教程，以后可从「帮助 → 新手教程」重看。
  3. 左上模板库内置 21 套模板（入门 / 页面与运行时 / 主题与 UI / 钩子 / 注册型能力 / AI 场景），选一套直接改。
  4. 「① 设计」页拖控件（结构控件决定能做什么、页面控件决定长什么样），点画布卡片在右侧改属性； 「② 代码」页可直接写 PHP / Python / HTML，也能把手工改动的 plugin.json / co.BEGG 同步回设计。
  5. 「③ 校验」全绿后，点「一键构建 ZIP」，或「④ 构建」页导出到目录。
  6. 解压到 plugins/<你的插件名>/，后台 → 插件 → 开启总开关（勾选风险确认）→ 启用该插件。

A2 · 浏览器版（不想装 Python 时）

  1. 双击 插件制作器.html（纯静态单文件，不用装任何东西，离线可用）。
  2. 选模板、拖控件、写代码、校验、下载 ZIP，步骤同上。

两个版本生成的文件完全等价，都对齐 v2 三文件契约；桌面版多了原生窗口、首次新手教程和 21 套模板。 桌面版可离线自检：python3 插件制作器.py --selftest（全部模板生成 + 校验 + 打包）。

办法 B：手写三个文件

最小可运行插件（纯 PHP 页面，不写一行 Go）：

plugins/hello/
├── plugin.json
├── register.go
├── co.BEGG
└── in.php

plugin.json

{
  "name": "hello",
  "title": "Hello 面板",
  "version": "1.0.0",
  "author": "you",
  "protocolVersion": 2,
  "pages": [
    { "name": "home", "area": "main", "title": "Hello 面板", "home": "in.php" }
  ]
}

register.go —— 是声明文件，不编译、不执行、服务器不用装 Go：

package hello

var Spec = PluginSpec{
    Name:            "hello",
    Version:         "1.0.0",
    ProtocolVersion: 2,
    Hooks:           []string{},
    Install:         []string{"in.php", "co.BEGG"},
    Runtime:         "php",
    Home:            "in.php",
}

co.BEGG

{
  "runtime": "php",
  "requires": ["php>=7.4"],
  "home": "in.php",
  "listen": "0.0.0.0",
  "pages": [
    { "name": "home", "area": "main", "title": "Hello 面板", "home": "in.php", "icon": "sparkles" }
  ]
}

in.php

<!doctype html>
<html><body>
<h1>Hello from plugin</h1>
<p>端口：<?= htmlspecialchars(getenv('NB_PLUGIN_PORT') ?: '') ?></p>
<p>站点：<?= htmlspecialchars(getenv('NB_PLUGIN_SITE_URL') ?: '') ?></p>
</body></html>

后台启用后，主界面侧边栏出现「Hello 面板」，点开就是 in.php。PHP 由服务器上的 php 解释器执行 —— 没装 PHP 的话，启用时就会明确报错，而不是装上了打不开。

2. 插件能做什么（4 类能力，可叠加）

能力 什么时候用 声明在哪
钩子 Hook（108 个） 想在「上传前拦截」「登录成功后通知」「请求进来时改写」等固定时机插一脚 plugin.json 的 hooks + register.go 的 Hooks
注册型能力 Provider（13 类） 想让宿主「点名调用你」当某种后端：存储、认证、通知、预览、支付、内容扫描、备份、恢复、CLI、搜索、主题、页面、AI 模型 plugin.json 的 providers / co.BEGG 的 providers
HTTP 页面 Page 想在后台/主界面加一个侧边栏入口，里面是 PHP / Python / Node / 任意网页 plugin.json 的 pages + co.BEGG 的 pages
UI 扩展点 侧边栏样式、主题配色、设置面板表单 co.BEGG 的 ui

纯页面插件可以一个钩子都不订阅，此时 plugin.json 不需要 entry（没有 JSON-RPC 子进程）。这是最轻量的形态。

3. 三文件契约逐字段

3.1 plugin.json（严格 JSON，未知字段直接报错）

字段 必填 规则
name ✅ 2–64 字符，只允许 [a-z0-9-_]，不能以 - 或 _ 开头。也是数据目录名
title — 展示名，留空回退成 name；≤128
version 建议 语义化 x.y.z（可带 -rc1 / +build）；≤32
author — ≤64
description — ≤512
protocolVersion ✅ 2（v1 老插件写 1，宿主自动兼容，不要求后两个文件）
hooks 三选一 钩子名数组，必须来自宿主 108 个钩子表；不能重复；最多 64 个
pages 三选一 PageDecl[]，见 3.3
providers 三选一 Registration[]，见 3.4
entry 条件 可执行文件名（单个文件名，不能含 /、\、 ..）。纯页面插件可省略
args / env — 传给子进程的参数与环境变量（别放密钥）
permissions — 权限声明，仅作记录与展示
license — 留空默认 AGPL-3.0-only
homepage / minHostVersion — 项目地址 / 最低宿主版本

hooks / pages / providers 不能三者皆空 —— 否则就是一个什么都不做的插件。

3.2 register.go（Go 语法的字面量，只读不编译）

宿主用标准库 go/parser 读语法树，取 var Spec = ...{...} 里的字面量。引用的类型可以根本不存在，也不需要合法 import。

  • 可识别的变量名：Spec / Plugin / PluginSpec / Declaration
  • 字段名大小写不敏感（Name 或 name 都行）
  • 只认字符串、整数、字符串切片、嵌套 map —— 不要写表达式、变量引用、函数调用
字段 说明
Name ✅ 必须等于 plugin.json 的 name
Version 非空时必须等于 plugin.json 的 version
ProtocolVersion 非 0 时必须等于 plugin.json 的 protocolVersion
Hooks ✅ 必须与 plugin.json 的 hooks 集合完全一致（顺序无所谓，内容必须一样）
Provides 注册型能力名列表（说明用）
Install 安装内容清单（说明用）
Runtime 非空时必须等于 co.BEGG 的 runtime
Home 非空且 co.BEGG.home 非空时，两者必须字面一致

这 4 项一致性由 crossCheck 强制。制作器会同时生成三份，天然一致；手写时最容易漏的是 Hooks 两边不同步。

3.3 co.BEGG（严格 JSON）

字段 说明
runtime ✅ php / python / node / go / binary / external
requires 解释器要求，如 ["php>=8.1"]、["python3"]、["node>=18"]。缺了解释器就在启用时直接报错，宿主不自动装、不静默降级
entry 入口脚本（相对 co.BEGG 所在目录）。python/node 常用
home 主页文件（相对 co.BEGG 所在目录），如 in.php / index.html。决定侧边栏点开显示哪个页面
static 静态文档根目录，默认取 home 所在目录
listen 写 0.0.0.0 表示「需要对外地址」；也可直接写 https://外部站/app
port 固定端口；0（默认）由宿主分配空闲端口
command 启动命令模板，占位符 {port} {host} {dir} {entry} {home} {static}。留空按 runtime 用默认命令
env 附加环境变量
pages PageDecl[]，见下
ui UI 扩展点，见第 6 节
providers 静态注册的注册型能力

PageDecl 字段

字段 规则
name ✅ 页面标识，只允许 [a-z0-9-_]
home 主页文件，相对 co.BEGG 所在目录
area ✅ admin（后台侧边栏）/ main（主界面）/ public
title 侧边栏显示名
icon lucide 图标名（如 sparkles、layout-dashboard），前端白名单映射
role admin / user / any（默认 any）
order 排序，小的在前
embed iframe（默认）/ newtab
public true = 宿主不做鉴权（透传，插件自负责）
url 外部 https:// 页面，填了就不反代，前端 iframe 直连

3.4 Registration 字段（13 类）

kind 宿主默认用哪个钩子调用
storage onStorageResolve
auth onAuthProviderResolve
notify onNotificationSend
preview onFilePreview
payment onPaymentCallback
contentScan onContentScan
backup onBackup
restore onRestore
cli onCLI
search onStatsCollect
theme onUIThemeApply
page onUIPageOpen
ai onAIProviderResolve

字段：kind（✅ 必须属于上表）、name（✅ 能力名，点名时用）、label（展示名）、hook（可选，覆盖默认钩子，必须是已登记的钩子名）、config（任意 JSON）。

4. 目录形式不限定，但三个「Dir」别混

plugins/hello/
├── plugin.json          ← ManifestDir（清单所在目录）
├── register.go
├── co.BEGG              ← BeggDir：页面服务的工作目录 + 相对路径基准
└── in.php

也可以按你举的例子，把声明和页面全塞进子目录：

plugins/ass-demo/
├── plugin.json
└── ASS/
    ├── register.go
    ├── co.BEGG          ← BeggDir = plugins/ass-demo/ASS
    ├── in.php           ← 所以 home 写 "in.php"，不写 "ASS/in.php"
    └── lib.php
目录字段 用途
Dir 插件安装根目录，始终等于 plugins/<name>/；JSON-RPC entry 的可执行文件基准
ManifestDir plugin.json 实际所在目录
BeggDir co.BEGG 实际所在目录；home / entry / static 都相对它解析

宿主递归定位三文件（深度 ≤ 5，跳过 . 开头目录、node_modules、__pycache__、vendor）。安装时整个源目录原样复制，不裁层、不挑文件；GitHub 下载的 zip 带一层顶层目录也能识别。

5. 钩子：三档能力与返回格式

5.1 三档

档 能力 返回
通知 知道某事发生了，不改结果 什么都不返回
决策 允许 / 拒绝本次操作 decision: "deny" + reason，或 error 里含 blocked
变换 改写上下文，影响业务参数 ctxPatch: {...}，浅层覆盖顶层键

5.2 火钩子的入参与出参

宿主 → 插件（fire）：

{"jsonrpc":"2.0","id":7,"method":"fire","params":{
  "hook":"onFileUploadBefore",
  "ctx":{"userId":1,"fileName":"a.txt","size":123,"ip":"1.2.3.4"},
  "seq":42
}}

插件 → 宿主：

{"jsonrpc":"2.0","id":7,"result":{
  "decision":"deny",
  "reason":"文件类型不允许",
  "ctxPatch":{"maxStorage":999999},
  "log":[{"level":"info","message":"checked"}]
}}

FireResult 字段：ctxPatch（变换）、error（含 blocked 即拦截）、decision（allow/deny/空）、reason、log。

同步钩子放在低频决策点；下载/预览等高频路径用 FireIf 轻量门 —— 没有插件订阅时零 IPC、零等待。

5.3 钩子分组（108 个，全部真接线）

分组 数量 典型钩子
文件管理 file 20 onFileUploadBefore（可拦截、可变换）、onFileDownload、onFileDelete
认证与会话 auth 10 onAuthBeforeLogin、onAuthLoginSuccess、onAuthRegisterBefore
分享 share 7 onShareCreateBefore、onShareAccess
系统生命周期 system 6 onBoot、onShutdown、onScheduledTick（每 5 分钟）、onHealthCheck
用户与权限 user 6 onPermissionCheck、onUserCreate、onUserQuotaChange
离线下载 task / WebDAV webdav / 存储 storage / 套餐 billing 各 5 onTaskComplete、onWebDAVPut、onStorageResolve、onPaymentCallback
内容治理 content / 协作 collab / 插件 plugin / UI ui 各 4 onContentScan、onCollabSave、onPluginEnable、onUIPageOpen
HTTP 请求 request / 通知 notify / 审计 audit 各 3 onRequestBefore（可拦截）、onNotificationSend、onStatsCollect
备份 backup / API api 各 2 onBackup / onRestore、onApiAuth / onCLI
AI 智能 ai 9 onAIRequest（可拦截外发）、onAIComplete、onAISearch、onAISummary、onAIAsk
限流 limit 1 onRateLimit

制作器的「代码 / 钩子」页内嵌完整 108 个（含中文说明、同步/异步、可否拦截、可否变换），勾选即自动写进两个声明文件。CLI 触发：nebula hook <command> [args...] → onCLI。

6. UI 扩展点（侧边栏 / 主题 / 设置面板）

全写在 co.BEGG 的 ui 里，前端通过 GET /api/plugins/ui 聚合渲染：

{
  "ui": {
    "sidebar": [
      { "page": "home", "title": "我的面板", "icon": "sparkles", "area": "main", "role": "any", "order": 10 }
    ],
    "theme": {
      "name": "ocean",
      "label": "海洋蓝",
      "css": "theme.css",
      "variables": { "--nebula-primary": "#0ea5e9", "--nebula-accent": "#38bdf8" }
    },
    "settings": [
      { "key": "greeting", "label": "问候语", "type": "text", "default": "Hello", "help": "显示在面板顶部" },
      { "key": "level", "label": "等级", "type": "select", "options": "1,2,3", "default": "1" },
      { "key": "enabled", "label": "启用", "type": "bool", "default": "true" }
    ]
  }
}
  • sidebar 是覆盖：按 page 名找到页面项，覆盖标题 / 图标 / 区域 / 角色 / 排序。页面本身还是要在 pages 里声明。
  • theme 走 CSS 变量覆盖（带注入过滤）+ 可选插件样式表，顶栏会出现主题选择器。
  • settings 支持的 type：text / password / number / bool / select / textarea；select 用 options 逗号分隔。保存走 POST /api/plugins/ui/settings/:plugin。

7. HTTP / HTTPS 页面是怎么跑起来的

  1. 宿主给插件分配一个本机端口，按 co.BEGG.command 起子进程，工作目录 = BeggDir。
  2. 通过环境变量下发：NB_PLUGIN_PORT、NB_PLUGIN_HOST（恒为 127.0.0.1）、NB_PLUGIN_NAME、NB_PLUGIN_DIR、NB_PLUGIN_HOME、NB_PLUGIN_SITE_URL、NB_PLUGIN_PROTOCOL。
  3. 宿主把 /ext/<plugin>/* 反代到 127.0.0.1:<port>。
  4. 前端侧边栏点开 → iframe 载入 /ext/<plugin>/in.php。

0.0.0.0 规则（你要求的行为）

插件写 listen: "0.0.0.0" 只作为「需要对外地址」的标记，真实 socket 始终收紧到 127.0.0.1。生成浏览器可访问的 URL 时按优先级替换：

  1. 后台绑定了域名 → 用域名；
  2. 只绑定了 IP → 用 IP；
  3. 什么都没绑定 → 默认 127.0.0.1。

php -S -t 的路径坑（宿主已处理）

php -S ... -t ASS 启动后文档根已经是 ASS/，此时请求 /ASS/in.php 会去找 ASS/ASS/in.php → 404。宿主用 PagePath 自动裁掉 static 前缀：home="ASS/in.php", static="ASS" → /in.php。所以你只要把 home 写成相对 co.BEGG 目录的路径即可，别自己拼前缀。

默认启动命令

runtime 默认 command
php php -S {host}:{port} -t {static}
python python3 {entry}
node node {entry}
go go run {entry}
binary {entry}
external 不起进程，前端 iframe 直连 pages[].url

Python 最小服务

import os
from http.server import SimpleHTTPRequestHandler, ThreadingHTTPServer
port = int(os.environ["NB_PLUGIN_PORT"])
ThreadingHTTPServer(("127.0.0.1", port), SimpleHTTPRequestHandler).serve_forever()

对应 co.BEGG："runtime":"python", "requires":["python3"], "entry":"server.py", "home":"index.html", "command":"python3 {entry}"。

鉴权边界（重要）

宿主对 /ext/* 完全透传：不校验登录态、不注入 token、不设 iframe sandbox，插件页面与宿主同源。插件自己负责鉴权。宿主唯一兜底是「全局总开关关闭 / 插件未启用 → 404」以及「开启总开关必须 acknowledge=true 免责确认」。

8. 可视化插件制作器使用说明

打开 插件制作器.html（单文件、纯静态、离线可用）。

区域 干什么
顶部 模板下拉（PHP 面板 / Python 看板 / 外部页面 / 主题包 / 纯钩子 / 空白）、导入/导出工程、一键构建 下载 .zip
左栏「控件库」 页面、侧边栏项、设置字段、主题、注册型能力、钩子分组 —— 拖到中间画布或点「+」添加
中间「画布」 插件结构树，拖动排序；右侧实时预览侧边栏 / 设置表单 / 主题配色效果
右栏「属性」 选中某个控件后编辑字段（含校验提示）
「代码」页 直接编辑 plugin.json / register.go / co.BEGG / 页面源码，语法高亮 + 实时校验
「校验」页 逐条列出宿主的校验规则（name、协议版本、三文件交叉一致、页面 area/role/embed、解释器 requires、路径越界……）
「构建」页 生成完整目录树、可复制单个文件、一键构建 导出 .zip

制作器保证生成物满足： - register.go 与 plugin.json 的 Name / Version / ProtocolVersion / Hooks 一致； - register.go 的 Runtime / Home 与 co.BEGG 一致； - 纯页面插件自动省略 entry，并在 pages 里声明页面； - home 写相对 co.BEGG 目录的路径，页面文件一定存在； - 选择的钩子一定来自宿主 108 个合法钩子表。

导出的 .zip 解压后整个文件夹丢进 plugins/ 即可（安装器递归定位，不挑目录层级）。工程文件（.pluginproj.json）可保存/回读，方便二次编辑。

9. 调试与排错（报错文本 → 原因）

报错 原因 / 修法

11. FAQ

Q：一定要装 Go 吗？ 不用。register.go 只是声明文件，宿主用 go/parser 读字面量，不编译、不执行。PHP / Python / Node 插件都不需要服务器装 Go。

Q：能用 PHP 写插件主体吗？ 不能拿 PHP 写 JSON-RPC 钩子主体 —— 但可以用 PHP 写嵌入页面（runtime: php + in.php），这正是最常见的用法。钩子主体需要一个能跑 JSON-RPC over stdio 的可执行文件（Go / Python / Node / 二进制都行）。

Q：v1 老插件要改吗？ 不用。protocolVersion: 1 的插件不要求 register.go / co.BEGG，宿主握手时对 v1 插件表现为 v1，钩子名与语义冻结，零改动继续跑。只是用不上 v2 的新钩子和页面/UI 能力。

Q：插件目录到底能不能随便放？ 能。三文件散落在不同子目录也行，宿主递归找（深度 ≤ 5）。唯一要注意：相对路径的基准是 co.BEGG 所在目录。

Q：为什么装上没反应？ 九成是「全局总开关没开」或「单插件没启用」。这是刻意设计的双层默认关闭。

Q：可视化插件制作器以后会怎样？ 当前是独立单文件工具（离线、拖拽 + 代码双模式、一键构建 zip）。正式版之后计划做成后台内嵌的可视化制作器；本次先把「一键构建」能力落地。

制作器里两个容易忽略、但已处理的坑

  1. NB_PLUGIN_DIR ≠ 文档根目录。宿主的 cmd.Dir 是 co.BEGG 所在目录（BeggDir），而环境变量 NB_PLUGIN_DIR 指向插件安装根目录。在 ASS/ 布局下若 Python/Node 服务脚本 chdir(NB_PLUGIN_DIR) 会找不到 index.html。制作器生成的 server.py / server.js 一律用当前工作目录作为文档根，不做 chdir。

13. AI 智能扩展（智能时代）

这一节是给「想让插件提供 AI 能力」的人看的。宿主内置了智能搜索、近期常用、代码空间、AI 助手、摘要与自动标签，但没有绑死任何模型厂商。

13.1 三档降级

档 谁提供智能 什么时候生效 你要做什么
L0 本地算法 宿主内置 永远 什么都不用做，联想词、近期常用、词法补全、提取式摘要开箱可用
L1 AI 网关 站长在后台填的 OpenAI 兼容端点 填了 key 且开启总开关 不用写插件，后台 → AI 设置里配置
L3 插件接管 你的插件 订阅钩子或注册 ai Provider 见下面两种方式

顺序是 插件接管 → 模型网关 → 本地算法。任一档不可用自动往下降，所以没配 key 时功能不会报错，只是「不那么聪明」。

13.2 九个 AI 钩子

钩子 档 能做什么
onAIRequest 同步 · 可拦截 · 可变换 模型请求发出前触发。写 decision=deny 阻止外发；写 ctx.prompt / ctx.model 改写请求
onAIResponse 异步通知 请求结束（成功/失败都发）。ctx.success / ctx.latencyMs / ctx.*Tokens
onAIProviderResolve 同步 · 可变换 注册型(ai)：点名调用 AI 能力时触发。写 ctx.handled=true + ctx.result 即完全接管
onAIComplete 同步 · 可变换 代码空间补全时触发（在网关之前）。写 ctx.completion 直接给结果，宿主不再调模型
onAIRecommend 同步 · 可变换 联想 / 近期常用 / 热门生成时触发。写 ctx.suggestions 或 ctx.fileIds 覆盖内置结果
onAISearch 同步 · 可拦截 · 可变换 自然语言搜文件时触发。写 ctx.filters（JSON）覆盖检索条件、写 ctx.answer 直接作答
onAISummary 同步 · 可变换 生成摘要/标签时触发。写 ctx.summary / ctx.tags 接管
onAIAsk 同步 · 可拦截 · 可变换 AI 助手问答时触发。写 ctx.answer 直接回答
onAIConfigChange 异步通知 后台保存 AI 配置后触发

钩子是同步的：ctx 是共享可变 map，插件通过 ctxPatch 回写的字段，宿主在 Fire 返回后直接读。不要在这些钩子里做耗时操作（宿主对单个同步 handler 有 5 秒上限）。

13.3 方式一：只订阅钩子（最简单）

插件订阅 onAIProviderResolve，收到请求后写 result：

{
  "name": "my-ai", "version": "1.0.0", "protocolVersion": 2,
  "entry": "plugin.py",
  "hooks": ["onAIProviderResolve", "onAIComplete"]
}

plugin.py 的 fire 分支返回：

if method == "fire" and params.get("hook") == "onAIProviderResolve":
    return {"jsonrpc": "2.0", "id": rid, "result": {
        "CtxPatch": {
            "handled": True,
            "result": "这是插件给出的回答（这里换成你的本地模型 / 私有 API）",
            "provider": "plugin:my-local-llm"
        }
    }}

宿主看到 handled=true 就采用 result，不再发任何外部请求。这也是「严格不出域」部署的做法：不填 key，只装一个本地模型插件。

13.4 方式二：注册 ai Provider（可后台点名）

在 co.BEGG 里声明：

{
  "runtime": "python",
  "requires": ["python3"],
  "providers": [
    { "kind": "ai", "name": "local-llm", "label": "本地大模型",
      "config": { "endpoint": "http://127.0.0.1:11434" } }
  ]
}

后台 → AI 设置 → 「能力提供方」下拉就能选到 local-llm。选中后宿主通过 CallProvider(ai, "local-llm", ctx) 点名调用，默认走 onAIProviderResolve（可以用 hook 字段覆盖成别的已登记钩子）。

plugin.json 里对应的 providers 也要写一份（三文件交叉一致规则不变），register.go 的 Provides 建议写 ["ai:local-llm"]。

13.6 隐私边界（务必写进你的插件 README）

  • 站长选择「配置即用」时，文件名与代码片段会发给所配的模型服务商；宿主不做强制脱敏，由插件与站长自行确认服务商条款。
  • 审计日志只记录 promptChars、tokens、latencyMs、成功/失败，不落 prompt 正文。
  • 插件如果要在 onAIRequest 里做脱敏，直接改写 ctx.prompt 即可，宿主会用改写后的文本发请求。
  • 不希望任何数据出域：不填 key，用 onAIRequest 拦截 + 本地模型插件提供 result。
